# 来源映射：从 10 份企划到 3 个候选概念

> 本文件回答一个问题：**三个候选概念里的每一样东西，是从哪份企划、哪份互评来的，改了什么，又扔了什么。**
> 不改动任何原稿。`docs/pitches/` 与 `docs/discussion/` 保持原样；本文件只做追溯与减法记录。
> 读法：**主骨**＝这一案的核心循环；**借层**＝只取一个可分离的零件；**—**＝未采用（理由见 §3）。

## 1. 逐案继承明细

### A《暖场》：把"停"做成一门手艺

| 来源 | 落点 | 改了什么 | 为什么 |
| --- | --- | --- | --- |
| 《静场》 | 主循环、16 步音序器、人潮＝液体、气口、冷场、评级 | 原样保留；补 4 种人潮行为修正 | 成本全在手感、不在范围；十案里收敛成本最低 |
| 《静场》 | 鼓棒举到最高点＝唯一合法出口 | 加"追光跟着鼓棒收束，最高点收成一条线" | 回应"判定圈没有标尺"的批评，让判定圈长在场景里 |
| 《静场》 | 失败比胜利好看（冲浪） | **改**：冲浪＝砸对之后多留 2 拍的贪心变体；假砸不给镜头 | 避免玩家故意追失败、把街机试错拖慢 |
| 《静场》 | 鼓手数拍（免费的公共时钟） | **改**：连续假砸，她 4 小节不打拍 | 把"可读性"变成要省着用的资源 |
| 《啸叫》 | 音乐时钟＝游戏时钟；卡面悬停先播一小节 | 降维成"编曲四选一 + 试听"，不引入乐理 | 让"停"之外有一层成长，但不把游戏变成作业 |
| 《满弦》 | 每次砸塌一块台唇 | 借用；6 块塌到 2 块，评分奖励"用最少的砸通关" | 给固定谱面一条向下压力曲线 |
| 《别关灯》 | 升级＝给一小节音乐 | 与《静场》的编曲选择合并成一套 | 两条讨论同时指向"用编曲替代数值卡"，只留一套 |
| 《杂音》 | 一拍一事件、关声可玩 | 升为全案验收 | 可读性是最便宜的质量线 |

### B《松手》：把舞台做成乐器

| 来源 | 落点 | 改了什么 | 为什么 |
| --- | --- | --- | --- |
| 《满弦》 | 主循环、六弦四人、向下成长、断弦地形、敌人无声、结尾一声"啊" | 原样保留 | 机制／主题／镜头同构最强，不可替换性最高 |
| 《满弦》 | 六弦全亮在 10:30（满配只剩 30 秒） | **改**：六弦齐鸣提前到 8:30，留 2:30 完整编制 | 回应"成型即终局"的批评 |
| 《满弦》 | 平行六弦 → 最优解是站着等 | **改**：踩下的 V 沿弦滑动，人潮能从弦缝钻过 | 逼出横向走位，避免"六道门"变成六个站位 |
| 《满弦》 | 断弦只能等队友装 → 可能雪崩 | **改**：第一根断弦脚本化、可救；最后一根进入"独奏"高光 | 让"穷"是 crescendo，不是罚站 |
| 《不散场》 | 缺声／补位：一个人走了，另一个人长出她的声部 | 借用；断弦后队友用别的方式补根音 | 让"失去"是编曲的变形，不只是数值 |
| 《啸叫》 | 终曲减配（每 2 小节少一个声部） | 借用，放到最后 8 小节 | 与"向下成长"同向，不需要额外系统 |
| 《杂音》 | 关掉声音也能玩、一拍一事件 | 升为验收 | 敌人无声，威胁必须靠视觉读 |

### C《谁在听》：把"看"做成资源

| 来源 | 落点 | 改了什么 | 为什么 |
| --- | --- | --- | --- |
| 《看向我》 | 主循环、光＝唯一资源且有代价、烧 vs 唱化、热度自衰减、人浪、空场结局 | 原样保留 | "看有代价"是最干净、最便宜的主动词 |
| 《看向我》 | 转化 1.5 秒 → 密度下停不住 | **改**：0.4 秒拉停、1.5 秒入座，两段到账 | 回应"密度不允许停 1.5 秒"的批评 |
| 《看向我》 | 无攻击键 → 可能被动 | **改**：左键收束＋烧；三根线要求跑动 | 让"看"与"跑"同时存在，保留低门槛 |
| 《第一排》 | 三根乐器线、脱插独奏、递麦镜头 180° | 借用；递麦改成终曲"放下光"，可失败 | 唯一"主动交出控制权"的动作；但必须能输 |
| 《第一排》 | 房间／曲库／setlist／静默场 | **不采用** | 长线层超出单机成品边界 |
| 《杂音》 | 三色、一拍一事件、拍线 | 拍线改成"目光—危险条"（被照人数 vs 循光噪音） | 把因果压成一维可读数 |
| 《请全体起立》 | 白光吃掉颜色＝血条；合唱团补音；无击杀数 | 借用；四声部对应四个座区 | 人气与血量共用一条视觉通道 |
| 《满弦》 | 灰→彩 0.8 秒、入场不是消失是坐下 | 借用，统一转化／唱化／安可回归 | 最便宜的一行动画 |
| 《回声四重奏》 | 观众只记得重复过的句子 | 借用为"观众"的副定义与结算文本 | 给"记得"一个成本，而不是一句文案 |

## 3. 明确丢弃：减法清单

| 丢弃 | 来自 | 理由 |
| --- | --- | --- |
| 4×4 循环器 + 起拍锁 BPM + 三章 + 约分 | 杂音 | 系统多、可读性互相打架；三章会把 M4 变成乐理课 |
| 一束灯在四个队友之间分配 | 别关灯 | 与《看向我》同源；四个去向 + 观众饿/抢/走 + 歌单＝一秒五件事，过不了一拍一事件 |
| 曲库／setlist／房间记忆／静默场 | 第一排 | 长线层超出单机单文件边界；只保"三根线 + 放下光" |
| 七段 12 分钟叙事 + 五角色 + 四种听法 | 不散场 | 情绪最强但收敛成本中高；只借"缺声/补位" |
| 六弦 + 四色观众同屏 | 六弦合唱（互评产物） | 两套信息体系叠加，必糊；弦归 B，色归 C |
| 回录 8 拍生成三个回声队友 | 回声四重奏 | 机制最原创，但音频调度与量化风险最高；只借"观众只记重复过的句子" |
| 评论区／应援牌／观众起名／二创墙 | 看向我、社区 | UGC 与真实平台影射风险；单文件成品不需要 |
| 双 Boss／三 Boss／多阶段演出事故 | 多份 | 一局只允许一个高潮事件；A 的"售罄"、B 的"回授"、C 的"静默"各一个 |
| 触屏／移动端／竖屏布局 | 旧模板 | 项目决策 0004：仅桌面键鼠 |
| 每日种子／排行榜服务器／账号 | 多份 | 离线单文件；本地最佳记录足够 |

## 4. 命名与合规

- 三个工作名：《暖场》《松手》《谁在听》。**均为工作名**，M3 定案后统一改名并做一次检索（标题、乐队名、场馆名、角色名、曲名）。
- 三份文件**不锁定角色名**，只用"主唱／鼓手／贝斯／吉他"指代。原因是 M1 报告已查出「小满」在三份企划中重复、「迟野／迟青／迟」近似；等 M3 选出一案后再统一命名，避免三案各自带一套撞名卡司。
- 不引用现实乐队、歌曲、歌词、艺人、动漫角色、商标；音乐全部程序化合成；不复制任何已知旋律与和声进行。
- **观众拥挤的表现红线**（写进 M4 美术方向）：不出现受伤、流血、窒息、踩踏；人群只用剪影与边光；"被按下去"必须立刻"笑着站起来"；失败画面停在空椅子、地上的手幅、扫地的店员，不落在具体的人身上。
- 内部文档可以出现类型名与技术名词（如物理建模算法名），但**不得进入游戏 UI、商店文案与宣传语**。

## 5. 利益冲突与自评声明

- 本文件作者（creative-director）是《啸叫》的作者。**《啸叫》没有成为任何一案的骨架**：它只以"音乐时钟／卡面试听／终曲减配"三个可分离零件进入 A 与 B。这样处理是为了避免"自己提案自己融合"的偏向。
- 三案的主骨作者分别来自不同成员：《静场》（arcade）、《满弦》（atmosphere）、《看向我》（community）。三案都不是"作者原案 + 补丁"，而是"主骨 + 两层可分离零件 + 一组讨论修复"。
- 我没有为任何一案写"它一定能赢"；三案的死法写在 `comparison.md` §7。
