## 0. 一句话与 30 秒规则

**一句话**：一首 6 分半的歌，一座会越唱越小的台子——你最强的招式是把全场按进沉默，等鼓手把鼓棒举到最高点，再把它砸回来。

**30 秒规则**：按住 `Space` = 收手（全场静音、人潮前压、张力充能）；鼓棒举到最高点时松手 = 砸（人潮开洞）。其余时间只做三件事：WASD 走位、左键落拍推人潮、每段结束选一段 8 小节编曲。唱到 6:30，别让场子冷掉。

**为什么它是"稳妥"的那一案**：整局只有一首写死的歌，所有声音、人潮形状、判定网格来自同一张 16 步表；没有程序化旋律、没有叙事分支、没有升级树、没有随机地图。音频即使降级成"节拍器 + 固定鼓点"，游戏依然成立。硬骨头只有一块：那 8 帧手感。

## 2. 核心体验与循环

**体验一句话**：你不是在清场，你是在把一屋子人按住，然后决定什么时候松手。

```
落拍推人潮 ─→ 人潮更挤 ─→ 读鼓棒 / 贴台唇 / 赌半拍
      ↑                              │
      │                              ▼
  下一段更密 ←─ 4 选 1 编曲 ←─ 砸（人潮开洞）←─ 鼓棒到顶，松手
                                              │
                                    假砸 / 憋过头 ─→ 气口↓ ─→ 冷场
```

- **秒级循环（1–3 秒）**：左键落拍把最前排推回去 → 看鼓手肩膀和鼓棒高度 → 决定还能不能再贴半拍。
- **十秒级循环（8 小节）**：收手 2–4 秒（全场最忙的两秒）→ 砸 → 人潮开洞 → 抢在合拢前归位。
- **分钟级循环（60–90 秒）**：一段唱完 → 4 选 1 编曲（改人潮形状与音色）→ 台唇少一块 → 下一段更挤。

**这一案没有雪球**。它不给你"越打越强"，只给你"越唱越准"：三次砸更省、四次编曲更懂歌、结算从 B 到 A。重开动力来自手法而不是数值。

## 3. 那个"哇"的瞬间：4:12 的那一砸

**0.00s**：你松手。麦克风啸叫被掐断——**1/32 拍的绝对空白**，不是变小，是抽走。
**0.02s**：底鼓不是"砰"，是一记 55Hz 下扫到 40Hz 的正弦。你能在胸口和桌面上同时感觉到它。
**0.05s**：16 盏灯在 3 帧内全部点亮，屏幕白了一帧——不是闪白，是过曝。
**0.13s**：最前三排像被一只手掌按进地里，然后笑着、骂着、一个接一个站起来。
**0.50s**：人潮里炸开一个洞。mosh pit 开了，洞的边缘在转，像水面上被戳了个洞。
**1.20s**：前排有人喊你的名字，喊得破音。

情绪落点只有一句：**"我刚才让一千个人安静了四秒，然后把他们全都撞倒了。"**

### 它如何在这一案里被保留

1. **8 帧是全项目最高优先级**，写在 M4 验收矩阵里：3 帧过曝、55→40Hz 下扫、2 帧镜头推、前三排"被按下去又站起来"。
2. **空拍必须是最忙的两秒**：读鼓棒、左键清前排、贴台唇、算还能不能多憋一拍；做不到这条，这一案作废（见 §8 风险 1）。
3. **关掉声音也能玩**：鼓棒、主唱的手、人潮的脚三个视觉等价物，静音跑一局仍要砸准 70% 以上。
4. **冲浪改法**：冲浪不再是"憋过头"的失败，而是**砸对之后多留 2 拍的贪心变体**——只有砸得准的人才配被举起来；假砸不给镜头，只给一个"嘁"。

### 它如何避开"黑场→观众接住你"

这一案的高潮是**你砸观众**，不是观众接住你。黑场不是救援，是你的武器。结局只有两种：安可（有人不想让你走）或冷场（人一层层退场，最后只剩一个人拍手）。全案没有任何"观众替你唱完"的时刻。

## 4. 关键机制

| # | 机制 | 规则 | 数值锚点（估计） |
| --- | --- | --- | --- |
| 1 | **按住—松手** | 按住：全场静音、人潮速度 ×1.7、张力 20/秒、可超充到 150；松手：按"张力 × 准头"结算。窗口＝鼓棒最高点 ±0.12s（完美）/ ±0.25s（稳）；早了＝假砸（清空张力、气口 −8、4 秒内鼓手不打拍） | 一次砸 3–5 秒；每段 1–2 个窗口 |
| 2 | **16 步单一数据源** | 一个 pattern 数组同时喂：音序器、刷怪、判定网格、灯光 cue、编曲选项 | 一小节 16 步，128 BPM |
| 3 | **人潮＝液体** | 总量／压力／前沿／热度四个标量 + 局部扰动；没有寻路、没有刚体 | 同屏 600–1000，低画质 400 |
| 4 | **气口＝血条** | 静场憋太久、假砸、长时间没有鼓点都掉；<30 人潮停止前压，0＝冷场 | 0–100，缓慢回复 |
| 5 | **台唇塌陷** | 每次砸塌一块，6 块塌到 2 块；评分奖励"用最少的砸通关" | 24m 台宽 → 终曲 9m |
| 6 | **编曲＝构筑** | 每段结束 4 选 1，6 个模块不重复：八分的墙／四连踩／切分／全场空／双踩／半拍拖；每张卡悬停先播一小节 | 一局 4 次选择 |
| 7 | **四条静止规则** | 鼓手＝秒表（举棒＝出口；追光跟着她的手收束，鼓棒最高点光斑收成一条线——判定圈不靠 UI；连续假砸她 4 小节不打拍）；贝斯＝护栏（低频按住前排，代价：张力上限 −15%）；吉他＝贼（静场中偷刮闷音清贴脸的人，代价：破坏完美判定）；主唱＝引信（你，唯一能移动的人） | 每多一人＝多一盏灯、一条规则、一个声部 |
| 8 | **失败＝冷场** | 气口归零：人潮退、手机屏对着别人、扫地店员进来；镜头不切走，停在台上 | 最后只剩一个人拍手，两下 |

**为什么没有"武器槽"**：武器就是四个人和这首歌本身；"变强"发生在编曲与人潮形状里，不发生在背包里。这样 M4 的卡池、进化、掉落全部不需要。

## 5. 预计内容规模（估计，M3/M4 锁定）

| 项 | 数量 | 为什么是这个数 |
| --- | ---: | --- |
| 角色 | **4**（1 可动 + 3 炮台，各一条静止规则） | "四个人一起停手"才是默契，少一个人就不成立；每多一人多一盏灯、一条规则、一个声部，边际成本线性、收益递减 |
| 武器／编曲模块 | **6 个 8 小节模块**（4 个槽位由段落决定，不重复） | 一局 4 次选择 × 2 个备选＝8 种组合；6 个模块刚好保证两局有一半不同 |
| 敌人 | **1 套人潮模型 + 4 种行为修正 + 2 种精英 + 1 Boss** | 敌人是参数不是 AI；加一种行为＝一组数字，加一个 Boss＝一段 script |
| Boss | **「售罄」**（场馆本体，3 阶段：压台／断电／清场） | 它不需要新模型：压台＝压力 ×2；断电＝8 小节只有鼓边；清场＝观众转身，你必须用一次完美砸把他们按回座位 |
| 关卡 | **1 座场馆 × 3 个灯光状态**（暖场／满场／清场） | 全部张力都在台唇那三米，换场馆不加玩法 |
| 曲目 | **1 首固定曲**（P1 可加 2 首，复用同一套 pattern 表） | 固定谱面是街机契约；多一首歌＝多一张 128 小节表，边际成本低，但 MVP 不需要 |
| 单局时长 | **6:30**（含安可判定 30 秒） | brief 下限 5 分钟；4 段 × 1 次编曲 + 3–5 次砸刚好；再长会把"固定谱面"的重复感暴露出来 |

## 6. 一局如何成立

| 时间 | 台上／台下 | 玩家在做什么 | 情绪 |
| --- | --- | --- | --- |
| 0:00 | 空场，灯只照舞台；人从门口陆续进来 | 学会落拍；第一次听见人潮的脚 | "我为什么要按得这么准" |
| 0:50 | 第一批挤到台唇 | 第一次收手 2 秒，发现自己在冒汗 | "原来停比按更吓人" |
| 1:40 | 第一次编曲选择 | 4 选 1，悬停试听 | "这一段是我写的" |
| 2:30 | 第一次假砸 | 鼓棒停在半空，前排有人"嘁" | 羞耻，但想再来 |
| 3:20 | 台唇塌第一块 | 贴边落拍，站位开始被压缩 | "台子在变小" |
| 4:12 | **最大一次砸** | 3–5 秒的屏息 | 全案的情绪核弹 |
| 5:10 | 最后一次编曲 | 明知终曲要来了，还要再赌一次 | "这首歌快唱完了" |
| 5:40 | 终曲最后一次砸 | 台子只剩中央 | 手在抖 |
| 6:00 | 三秒安静 | 不知道有没有人喊安可 | 全案最长的三秒 |
| 6:30 | 结算：S/A/B/C + 三个字母 +「再唱一遍」 | 输入乐队缩写（本地） | "再来一把我就走" |

**失败形状**：冷场。没有死亡画面，只有退场的人、地上的手幅、扫地的店员，和最后那个还在拍手的人。结算页不显示"你死了"，显示"场子冷在第 4 分 12 秒"。

## 7. MVP 与明确砍掉项

**MVP（能证明这一案成立的最小东西）**：
一间空场 + 一名主唱 + 一条 8 小节 loop + 3 次砸 + 1 种人潮 + 1 个冷场画面 + 1 张结算。**如果只能保一件事：按住—松手—砸响。**

**P0（GDD 锁定后的完整单局）**：4 角色、6 编曲模块、4 人潮行为、1 Boss 三阶段、3 灯光状态、气口、台唇塌陷、评级、暂停/设置/结算、`gbl.save.v1` 只存设置与最佳。

**明确砍掉**：
- 三章、约分、Boss 血量（这一案不靠血条）；
- 程序化旋律、每局不同的歌（固定谱面才是契约）；
- 角色专属武器、进化、掉落、商店、金币；
- 观众个性化、评论区、应援牌、结算长线（P2 都不做）；
- 第二场馆、第二首歌（P1 再谈）；
- 叙事分支与队友对白（"关系"留给 B/C，这一案只做默契）。

## 8. 最大风险

**风险 1（唯一能让全案归零）：那两秒空拍只是"罚站"。**
如果静场里没有信息可读、没有小事可做、没有判断可下，整个企划就退化成"等 CD 的游戏"。
**验收**：关掉声音跑一局仍能砸准 70%；测试者能说出"我在算还能不能再憋一拍"；静场里至少三件事可做（读棒／落拍／贴边／赌半拍）。做不到就砍掉这一案，不要修饰。

**风险 2：深度只有 4 次编曲。**
固定谱面 + 无成长，三局之后可能腻。
**对策**：三层压力撑住（台唇塌陷／气口／准头评级）；若测试仍腻，加的是"第二首歌"（P1）而不是新系统。

**风险 3：8 帧手感 + 音频调度精度。**
音频是这一案最轻的一环（可降级成节拍器），但判定必须跟 AudioContext 时钟，不能跟 rAF；否则"砸准"变成玄学。

**风险 4：6:30 是否太短。**
brief 允许 5–20 分钟；6:30 在下限之上，但评委可能认为"不够一局"。**对策**：M3 若要求更长，加"安可第二首"（同一张表、换 BPM），而不是把一段拉长。

## 9. 如何收敛成仅桌面 React + TypeScript + Three.js 的可玩版本

- **数据**：`patterns.ts` 一张表（16 步 × 5 轨 + 人潮修正 + 灯光 cue），刷怪／判定／音频全部从它派生；编曲模块、人潮行为、Boss 段全部是同一结构的数组。改数值不改结构。
- **状态**：单一 store（无 React 每帧 setState）；React 只做菜单／HUD／结算，HUD 以 8–10Hz 快照更新。
- **Three**：低多边形舞台（几十个面）+ 人潮 `InstancedMesh`（600–1000）+ 16 盏灯（不开阴影）+ 加法混合的光锥；白闪与过曝用 CSS/全屏 overlay，不做后处理管线。
- **音频**：16 步 lookahead 调度（25ms 前瞻），5 个音色 + 噪声；侧链压缩保证五轨不糊。**降级模式**：只剩底鼓与节拍器，视觉等价物接管节拍信息。
- **确定性**：曲目固定，只有人潮抖动与站位用种子 RNG；同一局可复现。
- **性能**：1280×720 起，60fps 目标；实体硬上限由技术方案定，粒子上限 200，低画质 DPR 降 1。
- **里程碑**：M4 锁 GDD/验收矩阵 → M5 七个实现模块（引擎／Three／战斗人潮／编曲与评级／数据／UI／音频）→ M6 候选版与实机 → M7 单文件 ≤2MB。
- **一旦手感不成立**：先做"只有一名主唱、一间空场、3 次砸"的手感切片（不接 UI、不接结算），两周内决定是否继续。

## 10. 为什么必须是少女乐队

因为"四个人在同一拍一起停手、又在同一拍一起回来"是默契，不是技能；因为 Livehouse 的前排离你只有三米，人就在你手边；因为乐手最怕的不是死，是没人再听。换成任何别的题材，"停"就只是一个蓄力键，"冷场"就只是一个失败画面。

## 11. 这一案留给评审的三个问题

1. 6:30 的固定谱面 + 只有 4 次编曲，深度够不够撑住"一局"？如果不够，你更愿意加"第二首歌"还是"第二种人潮"？
2. "空拍最忙"这条验收，应该由谁在哪个里程碑签字？如果 M5 原型答不出"这两秒你在忙什么"，是否直接判死？
3. 失败＝冷场（而不是死）会不会让部分玩家觉得"没有输赢感"？要不要保留一个"虽冷场但歌没停"的中间态？
