# 试玩反馈 08：无障碍 / 键鼠玩家

- **对象**：线上版 <https://yanyoo2000.github.io/girls-band-live/>（v1.0.0，无 `?dev`；Edge 156 / Chromium 156）
- **视口**：默认 1440×900 DPR2；缩放/最小尺寸测试 1024×640、900×560（DPR2）
- **方式**：Chrome DevTools MCP 实机操作；键盘用真实 `press_key`（Tab / Enter / Esc / 数字键 1–3 / 方向键），需要长按的用 keydown/keyup 保持 1.5–2.2s；对比度取自 DOM `getComputedStyle` 计算；OS 级 `prefers-reduced-motion: reduce` 在本机默认命中；用 CDP `Emulation` 验证 `prefers-contrast: more` 与 `forced-colors: active`
- **独立性**：只读 README「给玩家」段；未读 `docs/qa/playtest*`、`docs/feedback/*` 或其他试玩报告；未改代码、未 git、未安装
- **AI 声明**：无视觉/听觉；「看得见/好听」类结论不代替人眼人耳；截图见文末

## 首印象

标题页 → 主菜单的键盘体验是**专业水准**的：Tab 顺序合理、白色 2px 焦点环 + 4px offset 一眼可见，h1 拿到程序化焦点，有「跳到主要内容」跳过链接，屏幕阅读器会播报「主菜单 / 设置」等状态。

进演出后落差很大：舞台很暗，**光的位置和它照亮的范围在画面上几乎无法分辨**；唯一的操作提示是舞台上方一行 10px 灰字「Esc 暂停 · Tab 看构筑」；0:23 就弹出第一张核心卡。作为无障碍/键鼠玩家，菜单像 2026 年的产品，局内像 1996 年的 demo。

## 最好的 3 点

1. **键盘 UI 全流程真的走得完，而且焦点管理是专业级的。**
   菜单 → 演出 → 三选一（数字键）→ 暂停 → 设置（原生 range/checkbox/radio：方向键调音量、空格切选项，`aria-valuetext` 实时更新为 79%/70%/80%）→ 返回 → 离开确认（默认焦点在安全的「继续演出」）→ 结算 → 再演一场，全键盘闭环。对话框 `role=dialog` + `aria-modal` + `aria-labelledby`，打开时背景 `main[inert]`，关闭后焦点归还。菜单有 skip link、`lang="zh-CN"`、region/heading 结构、`role="status" aria-live="polite"` 播报路由。
2. **「高对比」和「减少动态」不是摆设。**
   打开后根节点 `.app` 立即带 `is-high-contrast` / `is-reduced-motion`；高对比把四区从纯颜色改成**形状编码**（前左=圆、前右=三角、后左=方、后右=菱形）+2px 描边，局内座位轮廓明显变清楚（06 图）；`prefers-reduced-motion: reduce` 在 OS 层命中时也会自动加 `is-reduced-motion`（本机实测 `matchMedia` 为 true）。
3. **Windows 强制高对比色（forced-colors）下外壳仍可读，结算页适合读屏。**
   forced-colors 下菜单按钮/面板获得系统描边、滑块变系统青色、HUD 文本变纯白，信息不丢（07 图）。结算页「散场之后」是 region + heading + 纯文本数据（峰值 128 / 时长 9:30 / 评级 C / 四区人数），屏幕阅读器可以顺畅从头读到尾，不需要猜条形图。

## 问题（severity + 复现 + 期望）

### P1 · high · 光、束光、点燃 100% 指针专属，键盘没有等价操作

- **复现**：拔掉鼠标（或全程不产生 pointer 事件）用键盘开一局。WASD 能走位，但光永远停在默认位置；无法选择照哪个区、无法点燃、无法回照。局 1 全程 0 次指针事件，光始终是默认散光。
- **证据**：`src/ui/input-dom.ts` `KEY_MAP` 仅 `KeyW/A/S/D`、`Arrow*`、`KeyE`；`beam`/`ignite` 只在 `pointerdown` 里设置。实际游玩中键盘可走位（局 2 镜头右移），但光不动。
- **影响**：这是 WCAG 2.1.1（键盘）级别的核心功能缺失——游戏唯一的核心动词「决定看哪里」无法用键盘完成。
- **反直觉证据**：纯键盘、零瞄准、零束光的一局反而拿到**峰值 128 + 完成终曲 C**（一般鼠标新手常见 30–74）。说明「不操作」比「按直觉按住左键」更安全，这个信号本身值得策划注意。
- **期望**：给光一套键位（例如 IJKL/小键盘移光、`K` 点燃、`L` 束光，或 Tab 选四区 + 回车点燃）；或提供「键盘辅助：光自动扫向有观众的区」的可选项；README/设置里明示纯键盘可玩到什么程度。

### P2 · high · 「人气 = 血量」没有可读的数字或趋势；读屏用户只能在空场后才知道输了

- **复现**：开一局，把眼睛闭上/用读屏听 HUD。可听到的只有「序曲 / 主歌」「前左区，热度抬头」「贝斯线断了」「安可未用」和进度条段落名；**没有任何观众数量/变化趋势**。
- **证据**：局内 HUD 里没有数字读数（设计上「不显示数字」）；`canvas` 是 `aria-hidden="true"` 且无 role/label；live region 只有「安可未用」「升级选择」这类事件。结算页才第一次出现峰值/终场数字。
- **影响**：低视力/读屏/色觉玩家无法判断「还剩多少血、是不是要输了」；这与「人气=血量=弹药」的核心契约冲突。
- **备注**：终曲段我在局 1 里没有按过 Space，结算仍写「完成终曲」——建议 QA 确认长按 Space 是必要的还是可选的（若可选，键盘玩家会误以为漏了操作）。
- **期望**：给读屏一个 5–10 秒节流的 sr-only 播报（「人气 28，下降中，危险」）；给低视力一个非数字仪表（环形/刻度/边缘亮度），不破坏「不显示精确数字」的设计。

### P3 · medium · HUD 字号 9–11px、关键提示 4.47:1，低于 AA

- **复现**：任意局内看舞台上方「Esc 暂停 · Tab 看构筑」；用 DevTools 读计算样式。
- **证据**：`.hud__hint` = `font-size:10px`，`color: rgb(111,122,138)` on `rgb(11,13,18)` ≈ **4.47:1**（< 4.5 AA）；段落名 11px（非当前段同色 4.47:1）；核心条 eyebrow 9px、卡牌分类 10px。
- **期望**：操作提示 ≥12px 且 ≥4.5:1（建议正文 7:1）；提供「HUD 字号」设置或让 HUD 跟随浏览器缩放（当前缩放会触发 P4 的锁死）。

### P4 · medium · 视口 <1024×640 直接全屏「窗口太小了」：无继续、无最低尺寸说明、无键盘出口

- **复现**：把窗口缩到 900×560 → 全屏提示「窗口太小了 / 本作只支持桌面键盘与鼠标。请把窗口放大到能看清舞台的尺寸。」；1024×640 正常。等价地，1440×900 上把浏览器缩放到 **200%（CSS 视口 720×450）也会触发**。
- **证据**：900×560 时 `Tab` 不聚焦任何控件、`Esc` 也关不掉覆盖层；提示没写最低分辨率，也没有「仍然继续」。
- **影响**：需要放大字体/页面才能看清的低视力用户，一放大就被完全锁在游戏外；小屏笔记本（1366×768 在 125% 缩放 ≈ 1092×614）也会中招。
- **期望**：提示里写明最低 1024×640；提供「仍然继续（可能看不清）」或降级 HUD 布局；至少让 Esc/回车能回主菜单，而不是只能改窗口。

### P5 · medium · 失焦/切标签**不暂停**模拟，只降音 + 清输入（与 README「失焦自动降音/冻结」不符）

- **复现**：局内把 `document.hidden` 覆写为 true 并派发 `visibilitychange`，等 8 秒。演出进度 60 → 68，即**隐藏状态下模拟照走 8 秒**；无暂停面板。
- **证据**：`src/main.tsx:266` 只在 visibilitychange 时 `setAudioHostHidden(engine, document.hidden)`；`src/ui/input-dom.ts:202-210` 只 `clearAll()`。没有暂停调用。
- **影响**：读屏用户切到浏览器设置/其他窗口，或用 Alt-Tab 查攻略时，回来可能已经空场；键盘玩家松开焦点期间也在掉血。
- **期望**：失焦自动暂停（显示「已暂停——按 Esc 继续」），或在设置里给「失焦暂停」开关；文档别写「冻结」。

### P6 · low–medium · 暂停面板构筑漏核心；两处焦点归还小瑕疵

- **复现**：局 1 已选核心「合唱墙」+ 7 张卡；Tab 开暂停，读「当前构筑」：只有逐张卡（擦弦、第一排……），**不列核心「合唱墙」**（标题行有核心名，但 region 内没有）。设置→返回暂停后焦点回到「继续演出」而非刚点的「设置」；「窗口太小」覆盖层出现又消失后，暂停面板曾出现焦点落在 inert 的 `main` 上，按一次 Tab 才回到对话框。
- **证据**：暂停面板 `region 当前构筑` 内只有卡；`h2` 描述行含「· 合唱墙」；`document.activeElement` 实测为 `main.app__screen[inert]`。
- **期望**：构筑区列出核心与进化；从设置返回时焦点归还到「设置」；覆盖层恢复时重新执行对话框 autofocus。

### P7（补充）· medium · 前 5:30 弹 10 次三选一，键盘/读屏用户的认知负荷过高

- **复现**：局 1 首卡 0:23，第 10 张在 5:28 完成；平均 ~30 秒一次，每次都冻结模拟、要求读 3 张卡各 2–4 行文案并做取舍。
- **期望**：把前 3 次选择拉开到 ≥60 秒；或提供一个「只按 1/2/3，不读文案也能玩」的简化卡面（卡名 + 一行效果）；读屏下把卡面长文案折叠成「效果/代价」两段。

## 最想优先改的 3 件事

1. **给光一个键盘等价**（移光 + 点燃 + 束光），并在设置/README 写清纯键盘能玩到什么程度。（P1）
2. **让人气与危险可读**：sr-only 趋势播报 + 低视力非数字仪表（P2），并把 HUD 提示提到 ≥12px、≥4.5:1（P3）。
3. **拆掉 1024×640 的硬锁死**：说明最低尺寸、提供「仍然继续」、允许 200% 缩放下进入游戏（P4），同时修失焦不暂停（P5）。

## 评分（1–10）

| fun | theme | clarity | performance |
| --- | --- | --- | --- |
| **5** | **8** | **4** | **8** |

- fun：菜单/结算/主题很带感，但作为键鼠玩家，局内只能「看」不能「看哪里」，第 2 局开始就腻。
- theme：四区=四声部、光=目光=人气、后台台词、散场之后，落地非常扎实。
- clarity：UI 流程清晰，但局内核心状态（光、人气、危险）对非视觉玩家几乎不可读。
- performance：1024×640 DPR2 下 rAF **143fps**（本机 RTX 4080 级）；高对比/减少动态无卡顿；后台标签会被节流，且不会暂停（见 P5）。
- 补充：节奏结构（10 次三选一集中在 5:30 前）作为音游/节奏视角的问题不重复计分，仅列为 P7。

## 是否再玩 / 推荐

- **是否再玩**：愿意。想用**键鼠**完整跑一局回照/引线（纯键盘只能「看」，不能「决定看哪里」）。
- **推荐**：会推荐给**能用鼠标、需要高对比/减少动态的玩家**（这两项做得好）；**不会**推荐给只有键盘、只用读屏、或需要放大到 150%+ 才能看清的玩家——当前这四类人在局内会被卡住。
- 一句话：**外壳是 9 分的无障碍，核心玩法是 2 分的无障碍。**

## 限制说明

- AI 无人值守：键盘为 DevTools 合成事件（`isTrusted=false`），但走的是游戏真实监听器；鼠标指针从未在局 1 里移动（这是「纯键盘」结论的基础）。
- 未做真实人耳听感/人眼观感验收；对比度为 DOM 计算值，不包含 canvas 内的 3D 亮度（世界过暗问题由视觉试玩覆盖，本文不重复）。
- 未验证 Firefox/Safari、真实 NVDA/VoiceOver 朗读（只按 a11y 树与 aria 属性评估）、真实 Alt-Tab（用 `document.hidden` 覆写替代）。
- 「窗口太小」阈值按 README 1024×640 + 1024×640/900×560 两点实测，未逐像素标定。
