# 试玩反馈 05 · 音频 / 音乐制作视角

- 试玩员：`playtester-05-audio`（独立试玩，未阅读其他试玩报告）
- 版本：GitHub Pages 公开版 `https://yanyoo2000.github.io/girls-band-live/`（普通 URL，未用 `?dev`）
- 环境：Chrome DevTools MCP，isolated context，1440×900 视口，Windows；WebAudio 采样率 44100 Hz
- 时长：真实会话约 30 分钟；**2 局完整**（第一局「空场完成」C / 9:30；第二局「完成终曲」C / 9:30）
- 工具约束（必读）：
  1. **我是 AI，没有耳朵，无法做听感验收**。本报告不判断"好不好听/音色是否漂亮/混音是否平衡"，只评 WebAudio 行为、增益/调度数值、界面反馈、可视化节拍与代码结构。凡涉及听感的结论都必须由人耳盲听补验。
  2. 自动化环境里鼠标/键盘只能合成，长按（束光、终曲 Space）与"完美窗口点燃"无法可靠复现；这会影响转化率与合唱人数，相关结论已按"低人气局"限定。
  3. 该浏览器所有页面都被视为 visible，真实失焦只能用 `document.hidden` 覆写模拟；已注明。

## 一、首印象

"光的三种去向 = 注意力预算"这个概念在音频上是有落点的：**段落推进 → 编曲层数增加**（序曲 2 层 → 主歌 4 层 → 副歌/终曲 5 层），我实测的增益表与数据/代码完全对得上。HUD 的节拍环、舞台脚下的拍点脉冲，与 128 BPM、4/4 的时钟同源，属于"看得见的节拍"。

但第一局给我的最大印象是**听众席几乎是黑的**：屏幕上只有舞台附近少量观众被点亮，12 声部合唱的增益长期在 `0.004–0.024`（相对音乐总线 0.7–1.0，约 −30 ~ −45 dB）。对一个以"你照亮谁，谁就为你唱"为主题的游戏，**"合唱"在常规局里几乎没有存在感**——这可能是我操作差（合成鼠标），也可能是校准问题，需要真人复核。

## 二、三件最好

1. **段落 → 层增益的设计与实现一致，且切段无爆音**
   - 序曲：`drums 1.00 / bass 0.90`，chords/lead/arp = 0（2 层）
   - 主歌 1:30：`1 / 0.9 / 0.85 / 0.8 / 0`（4 层）
   - 副歌 3:41：`1 / 0.9 / 0.85 / 0.8 / 0.7`（5 层）
   - 终曲 7:40：5 层全开
   - 切段用 `setTargetAtTime(…, 0.12)`（`src/audio/music.ts:130`），实测值单调过渡，没有瞬时跳变；层表与 `BASE_GAIN` 完全吻合。
2. **12 声部合唱池是"真 12 声部"，结构干净**
   - 页面启动后 `oscLive` 恒为 **12**（峰值 13，多出的 1 个是调度用的短音符），4 区 × 3 层（近/中/远）各 1 osc + 1 gain + 1 panner；每小节更新和弦（`setChoirChord`），声像 `-0.35/0/0.35` 扇开，另有 1 条呼吸噪声。
   - "逐层加入 + 总线每层 −3 dB 补偿"（`src/audio/choir.ts:171-183`）的思路正确：目标是**变厚不变响**，不是单纯拉音量。
3. **暂停 / 失焦 / 三路音量的工程行为是对的**
   - `Esc` 暂停 → `AudioContext.state = "suspended"`（真正挂起，不是假暂停）；继续 → `running`。
   - 模拟页面隐藏（`document.hidden=true` + `visibilitychange`）→ `masterGain 0.8 → 0.096`（`HIDDEN_DUCK=0.12`，`src/audio/engine.ts:57`），恢复 → 0.8，保留拍点连续性。
   - 设置里三路音量即时生效：主 0.4 → `masterGain=0.4`；音乐 0.2 → `musicBus=0.2`；音效 1.0 → `sfxBus=1.0`（中间值 0.448 是 `setTargetAtTime` 的渐入过程，不是 bug）。

## 三、五个问题（severity / 复现 / 期望）

### P1（medium-high）空场后音乐被静音，且可能整局不恢复

- **复现**：第二局，观众被打空后 HUD 出现「空场。只剩你还在弹。」；此时 `silenceGain = 0`（音乐、乐队层、合唱、房间底噪全部静音），但**文案说"只剩你还在弹"**。实测直到 6:30–6:45 的 Boss 静默状态翻转后，`silenceGain` 才回到 1（run 408 读到 1）。若空场发生在 6:45 之后，这一局剩余时间将**完全无音乐**，结算页也一样。
- **根因（代码）**：`src/game/store.ts:1324-1327` 在 `present === 0` 时直接 `deps.audio.setSilenced(true)`，但 `silencePrev`（`store.ts:1212-1218`）没有被同步；下一个 tick `silentNow=false`、`silencePrev=false`，**不会调用 `setSilenced(false)`**。`applySilence` 的守卫 `if (!silenced && gain.value >= 0.999) return` 也拦不住已经为 0 的总线（`engine.ts:442-459`）。
- **期望**：空场不要复用 `silenceGain`（它是"系统抽走声音"的专用总线）。要么给空场单独的 `emptyHouseGain`（只 duck 乐队、保留主唱/合唱），要么在 `setSilenced(true)` 同步 `silencePrev = true` 并保证有恢复路径。空场叙事是"一个人弹完"，此时**更应该有声音**而不是更安静。

### P2（medium）静默段恢复是 30ms 硬切，且不量化到小节

- **复现**：6:30 进入静默（`SILENCE_FADE=0.03s`，`engine.ts:59`、`451-457`），实测静默期间 `dOsc=0 / dBuf=0`（调度在 `engine.ts:499` 因 `state.silenced` 直接 return，连 SFX 也没有新 buffer）；6:45 恢复时也是 0.03s 斜坡。
- **风险**：30ms 足够防爆音，但"抽走/塞回"的听感会很硬（无法由我人耳判定）；恢复时 `stepIndex` 只是 `stepAt(now)` 对齐到当前 16 分步（`engine.ts:565-566`），**可能从半拍/弱拍开始**，对依赖拍点（点燃完美窗口 80ms）的玩家来说，恢复瞬间的节拍相位可能对不上 HUD 节拍环。
- **期望**：恢复量化到下一小节（bar）或强拍，并给 1 拍 fade-in；静默进入可以是硬切（设计意图），但**回来**需要可预期。

### P3（medium）12 声部合唱在常规 C 评级局几乎不可闻

- **复现**：两局峰值人气 32 / 61。12 个声部增益实测 `0.004–0.024`，音乐层 `0.7–1.0`；按 `sqrt(layerAudience/64)*0.22*trim`（`choir.ts:180`），单区 64 人才到 0.22，而我两局单区人数常为 0–2。
- **问题**：卖点是「12 声部合唱」，但在**常规结局（C，峰值 32–61）**里它相对音乐低 30–45 dB，基本等于不存在；只有把人气养到数百才听得出"变厚"。如果设计上就是"B 级以上才配听合唱"，需要明示；否则这是校准问题。
- **期望**：给合唱一个"感知下限"（例如人气 ≥8 时抬到约 −18 dB），并在侧链/频段上为它让位（lead/arp 让出 1–2 kHz）；同时保持"变厚不变响"的补偿逻辑不变。

### P4（low-medium）升级三选一弹窗期间音乐继续，且弹窗频率打断段落

- **复现**：第一局 0:30 第 1 次、2:32 第 5 次、3:58 第 7 次（10 次集中在 3:48 内，与 README 已知限制一致）。弹窗打开时游戏时间冻结（run 72s、HUD revision 157 不变），但 **osc 1576→1995、buffer 1607→2038 持续增长**——音乐没停。
- **问题**：画面暂停而音乐继续，玩家会以为"卡住了"或"在放 BGM"；同时高密度弹窗把 5 段音乐结构切碎，音频负责人最在意的"层切换叙事"被三选一打断。
- **期望**：升级弹窗按暂停处理（`audio.suspend()` 或 `musicBus` duck 到 0.2 + 低通），或在弹窗期间只保留鼓/贝斯（"排练继续"）并明确 UI 提示。

### P5（low）静默段"死寂"：连心跳/SFX 都没有；失焦只验证到"降音"

- **复现**：静默 15 秒（6:30–6:45）采样 `dOsc=0`、`dBuf=0`，**没有任何 SFX buffer**。README 与 `engine.ts:442` 注释说"静默段只保留心跳"，但实测没有心跳（`sfxBus` 不经过 `silenceGain`，问题不在总线，而是静默期间没有 cue）。
- **另外**：真实失焦无法在自动化浏览器里触发（所有页 `document.hidden=false`），我用覆写模拟验证了 `HIDDEN_DUCK`；真实隐藏时 rAF 冻结导致"暂停"的部分**未验收**。
- **期望**：静默段固定每 2 拍一条低频心跳（`sfxBus`，−20 dB 左右），把"无声"做成"只剩心跳"；并在静默开始/结束时给一个明确的 HUD 文案（当前只有音频变化）。

## 四、最想优先改的三件事

1. **修空场静音（P1）**——这是唯一一处会让玩家在结局"听不到音乐"的确定性问题，且与文案矛盾。
2. **合唱可闻性（P3）**——12 声部是这个游戏音频卖点的核心；常规局听不到等于没做。建议先做一次"人气 32/61/128/256"四档的盲听 A/B，再定下限。
3. **静默段回来要"可预期"（P2）+ 保留心跳（P5）**——静默是全场唯一一次"系统拿走声音"的高光，恢复的量化与心跳会让它从"bug 感"变成"设计感"。
