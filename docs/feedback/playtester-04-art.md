# 试玩反馈 04 — 视觉 / UI 设计师（playtester-04-art）

- **版本**：GitHub Pages 在线版 <https://yanyoo2000.github.io/girls-band-live/>（与 `dist/girls-band-live.html` 同一构建）；辅助用 `file:///…/dist/girls-band-live.html?dev=1` 快进看后期/结算。
- **环境**：Edge（Chromium），1440×900 CSS / DPR 1.5（backing 2160×1350），键盘 + 鼠标，未开高对比/减少动态。
- **方法与局数**：
  - 局 1（线上版）：从「点击开始」→ 主菜单 → 演出，实际推进到主歌 2:37、第 6 次三选一（中途用脚本扫光/点燃，升级卡与暂停均用真实键鼠）。
  - 局 2–3（dev 版，同一构建）：用 `__gbl.store.tick` 快进到空场结算（3:23，评级 C）与第 69 秒空场，专门看后期、白光与结算画面。
  - 局 4（dev）：重开一局看暂停面板与设置页。
  - 合计 4 局、约 25 分钟（其中线上实机约 12 分钟）。dev 快进只用于"把画面推进到后期"，所有观感判断仍以线上实机画面为准，报告内已标注。
- **独立性**：只读了 README「给玩家」段；未读 `docs/qa/playtest*`、`docs/feedback/*` 或任何其他试玩报告。

## 一、首印象（30 秒内）

**"这是一张会呼吸的 Livehouse 海报，但海报里的场馆没开灯。"**

首屏很好：纯黑底、发光大字「谁在听」+ `WHO'S LISTENING`、一句宣言文案、一个暖白主按钮，没有任何多余元素，加载零等待——像成熟商业作品，不像 AI 产物。主菜单延续同样的气质：左侧标题+纵向菜单，右侧四名成员卡（江栖/许燎/闻笙/邵砚，色块+极简剪影）与「散场之后·最佳」。

但点进演出后的第一分钟，观感急转直下：**整屏太黑**。观众席 768 个座位在 1440×900 下几乎是一块黑布（实测截图平均亮度 19/255，舞台区域 23/255）；看不到"光"在世界里的位置，看不到噪音，也看不清"谁被照亮了"。核心动作「照向台下」在画面上没有视觉落点，玩家只能靠 HUD 那条「目光/危险」横条猜测自己在干什么。这不是"氛围黑"，是**黑到剥夺了游戏的主要读屏手段**。

---

## 二、3 个最好

1. **「散场之后」结算页（`10-散场之后结算.png`）**——全场最佳。标题「散场之后 / 再亮一会儿 / 空场完成 / 今天，只有你听见了。」+ 打折卡式的 C 评级 + 「今晚有 7 个人第一次站起来；第二排还空着 64 个位置。」的数据化台词，情绪和叙事都成立，是**最想分享出去的一屏**。
2. **白光（whiteout）的"生理感"（`09-空场白光.png`）**——whiteout=0.85 时四周强烈泛白、四个区标签被"烧"成白色胶囊，视觉冲击很强，确实传达了"你正在失去他们"。方向对，只是需要控制它吃掉的信息。
3. **品牌与文案的一致性**——暗底 + 暖白主色 + 青/黄/品红点缀；按钮、卡片、焦点环、评级卡、设置页都同一套语汇；Livehouse 用语贯彻到底（调音台、回后台、安可、散场）。在"零外部素材、程序化生成"的约束下，这套视觉体系完成度很高。

## 三、5 个问题（severity + 复现 + 期望）

### P0-1｜全场景过暗，观众/噪音不可读
- **现象**：开局到主歌，观众席在画面上是一整片近黑；只有零星白色锥体，看不出"768 座""哪个区有人""噪声覆盖到哪"。HUD 明说"被噪音覆盖"，画面里却找不到噪音实体。
- **复现**：线上版 1440×900，开局任意时刻截图（`03-开场演出.png`、`06-演出-主歌.png`、`07-演出-2m37s.png`）。用 Pillow 统计：整图平均亮度 **19/255**，舞台区域 **23/255**；观众席 99.9% 像素 R/G/B < 40。
- **期望**：序曲至少让"人"能被数出来——被照亮的座位/观众有明显亮度差（例如 +2~3 档），未照亮座位保留轮廓光；噪音用自发光描边或反相色块，保证在暗底上能一眼定位。可加"低画质/高对比"下的备用描边方案。

### P0-2｜"光"在世界里不可见
- **现象**：无论散光、还是按住左键 2.5 秒的束光，画面里都找不到光斑/光锥/被照亮的区域；玩家只能看顶部「目光」条。核心机制（三种光形态）在画面上没有可读的变量。
- **复现**：线上版开局，鼠标移到画面 30%/50% 处并按住左键 2.5 秒，前后截图（`03-开场演出.png` → 未在报告展示的 `11-beam`）。像素差仅 **9,006 / 5,184,000 = 0.17%**，且分布全屏（HUD 文本抖动），观众席区域变化 4,151 px（0.2%）——没有可识别的世界光效。
- **期望**：给光一个"看得见的体积"——地面照亮圆斑 + 半透明光锥 + 被罩观众整体提亮/加边；束光/散光/回照用半径与色温区分（回照给脚下环形护盾）。至少要能回答"我的光现在在哪、照到谁"。

### P1-1｜升级三选一打断节奏，卡面信息密度过高
- **现象**：开局几乎立刻进入升级，并在极短时间内连弹。线上局 0:00→3:00 之间出现 6 次三选一（`04-升级三选一.png`→`05-第二次升级.png`→`08-白光-升级遮罩.png`）；dev 快进数据显示：第 19.4/34.6/55.7 秒各一次（57 秒内 3 次），到 94.6 秒已 5 次。每次都要停下来读 3 张 4 行文案，且"按 1/2/3 也可以选"。
- **期望**：开场把"选核心"和第一次升级合并为一次；后续升级曲线稀疏且用图标+关键词+一行效果呈现，代价用红/橙标签，详情放 hover 或二级页；升级弹窗不要盖住整个舞台（可缩成侧栏卡片）。

### P1-2｜卡片顶部的三个圆形"旋钮"没有信息
- **现象**：每张升级卡上方固定一排 3 个圆形图标（灰色旋钮状，见 `04-升级三选一.png`、`05-第二次升级.png`、`08-白光-升级遮罩.png`），既无标签也无状态变化，看起来像可点的音量旋钮/档位按钮，实际无交互。
- **期望**：换成能表达卡牌类型的图标（合唱/独奏/招灾/通用），或直接删除；若保留"档位"语义，需要可读的填充状态。

### P2-1｜HUD 小字可读性差，且白光会淹没 HUD 文本
- **现象**：
  - 左下「核心」卡片的卡名/卡标签、底部「Esc 暂停 · Tab 看构筑」、升级页「不能重抽…」提示，都是 11–12px 灰字，在暗背景上对比度不足（`03-开场演出.png`、`06-演出-主歌.png`）。
  - whiteout=0.85 时左上「前左」/右上「前右」等区域标签整块变白，文字消失（`09-空场白光.png`）。
  - 复现了 README 已知限制 10：暂停面板「当前构筑：还没有拿到卡」，但 HUD 已显示核心「回照」（`12-暂停面板.png`），同一状态两处说法矛盾。
- **期望**：HUD 文本统一提升到可读对比（≥4.5:1）与最小字号；白光叠层在 HUD 之下或在文字处退让；暂停面板读取与 HUD 同一份构筑数据。

（另记两条低优先：结算页 12 项数据挤在一个卡片里，字号偏小；设置页「减少动态/高对比/低闪」的说明字也是灰 12px。）

## 四、最想优先改的 3 件事

1. **让"光"和"人"在画面上可见（P0-1 + P0-2 合并）**：这是"看得懂"的地基。序曲把观众席提亮到可辨认，给光加地面光斑 + 体积光锥 + 被罩观众提亮，噪音加自发光边。哪怕只做"被罩观众整体亮一档"，也比现在强。
2. **重构升级节奏与卡面信息（P1-1 + P1-2）**：开场合并首次核心选择，后续稀疏；卡面改为"图标 + 关键词 + 一行效果 + 代价标签"，删掉三旋钮。
3. **HUD 分层与白光收敛（P2-1）**：小字提对比、白光不吞 HUD 文本、暂停面板与 HUD 共用构筑数据。

---

## 五、是否再玩 / 推荐

- **是否再玩**：**愿意，再玩 1–2 局**——前提是把亮度/光可见性修好；目前我"玩不懂"的原因不是玩法不好，而是画面没告诉我光在哪、谁在唱。
- **是否推荐**：推荐给喜欢氛围向、愿意读文案的实验性 roguelite 玩家；会附一句"把屏幕调亮，先看 HUD 再看台下"。对追求即时反馈的玩家暂时不推荐。
- **一句话**：美术底子很好，情绪和品牌都在线；先把"看得见"补上，这款游戏的传播力会立刻上一个台阶。
