# 试玩反馈 03 · 音游/乐队粉丝视角

- 试玩员：playtester-03-rhythm（独立试玩，未读其他试玩报告）
- 对象：**在线版** https://yanyoo2000.github.io/girls-band-live/ （v1.0.0 Pages），1280×720 CSS / DPR 2 窗口，Chrome，硬件加速开启
- 时间：2026-10-28 10:45–11:32（约 47 分钟），含菜单/设置/曲目单探索 + 2 局演出
- 依据：**截图 + 界面文本 + 源码结构 + WebAudio 节点/电平测量**；**我无法真实听音**，因此下文所有关于“听感/音色/是否好听”的结论都只写结构与测量，不伪造听感。

## 0. 先说最重要的局限（请连同结论一起读）

1. **AI 没有耳朵**：我能读到 5 层编曲、12 声部合唱池、和弦表、静默增益节点的代码与运行期节点数量，也能用 AnalyserNode 测 RMS，但**不能判断“好不好听”“少一轨疼不疼”**。本报告不包含任何听感评价。
2. **自动化输入第一局打偏了**：第一局我向 `canvas` 派发指针事件，实际监听在 `#root`（`src/main.tsx:174`），所以**第一局的“光/点燃”没有真正进入游戏**，那一局的 157 次转化来自自动系统（返听/人浪/卡牌）。第二局（`?dev=1`）修正后确认光位会跟指针移动，但受工具 10 分钟级回合延迟影响，**核心操作手感（0.15s 光惯性、2 拍点燃冷却、完美窗口）没有得到稳定的人手验证**。
3. 因此：**界面、画面、结果页、代码结构、音频图结构**是本报告的强证据；**“打起来爽不爽”**只能给保守判断，并明确标注。

## 1. 首印象

标题页与主菜单非常克制、干净：`留声 / 谁在听 / WHO'S LISTENING` + “你只有一束光。照向台下，他们为你燃烧，噪音也循光而来。” 这一句比大多数独立游戏的口号更准，主题（注意力=演出=危险）在第一屏就成立了。成员卡（江栖 主唱·光 / 许燎 主音吉他·高频 / 闻笙 贝斯·低频护盾 / 邵砚 鼓·节拍）把“乐队”写进了系统词汇，而不是贴皮，这是好兆头。

但进入演出后的第一分钟是**反高潮**：画面极暗，座位区是一整片暗色矩形，看不到观众、看不到光斑落在人身上，也听不到（我无法听）任何能确认“我刚刚照亮了谁”的反馈；我唯一的“光”线索是屏幕右上角一个白色小球加一条细绿线，以及舞台后方几支锥形道具灯。第一张卡在 0:50 左右弹出，我还在找“人在哪里”。

## 2. 三个最好的点

1. **结算页是整款游戏最强的一段**（`08-result-C.png`）。`散场之后 / 今晚的账 / 空场完成 / 今天，只有你听见了。` + `真实数据`（峰值 50、终场 0、转化 157、烧死 26、被覆盖 99、离场 172、空位 768、第二排空位 64、安可 未用、裂缝 3、时长 9:30）+ `后台` 四个成员各自一句（“贝斯断了 1 次，返听咬了你 2 次”）。它不哄人、给真数，还用成员口吻把失败写成叙事；评级 C「只剩一盏灯」也不羞辱玩家。这是“乐队”主题真正落地的地方。
2. **节拍真的进了玩法，不是装饰**。`src/data/music-clock.ts` 是单一权威时钟（128 BPM、4/4、bar/beat/beatPhase）；`src/game/light.ts:330-388` 的点燃判定按到拍距离分 `perfect / good / off`（倍率 1.6 / 1.2 / 0.4），再乘“区和弦内 ×1.25 / 和弦外 ×0.75”与扫场奖励，XP 3 / 2 / 1，冷却 2 拍；卡池里还有 `节拍点燃（完美窗口 80→120ms）`、`灯下合唱（完美点燃后 8 拍 +30%）`、`擦弦（每 8 拍自动转化 1 名观众）` 这种直接改写节奏规则的卡。**这是音游向的设计，而不是“有 BGM 的幸存者”。**
3. **音频结构做得比“能响”深得多**。5 层乐队（drums/bass/chords/lead/arp）按段落换层；和弦表 10 个和弦、每 4 小节自动升七和弦；鼓有 16 分固定 groove 偏移与力度表；12 声部合唱 = 4 区 × 3 层，**每区固定唱当前和弦的一个声部（根/三/五/七）**，层按人数 0–64 / 64–128 / 128–192 逐层加入，并做 −3dB/层的总线补偿（“变厚不变响”）、热度 detune、呼吸底噪、压缩器；静默段把合唱总线 30ms 内切 0。设置页还给了 `节拍脉冲（关声仍可玩）`、`低闪（≤3Hz）`、`减少动态`、`高对比`——无障碍意识在线。运行期实测：1 个 AudioContext running，前 6 分钟创建并启动约 8200 个振荡器、5800 个 buffer source；Analyser 实测 RMS 0.033–0.231（音乐持续存在、有动态）。**这些是“声部设计”，不是把音量拧大。**

## 3. 五个问题（severity / 复现 / 期望）

### P1 · 观众在画面里几乎不可见，因果反馈断了
- 复现：任意一局进入演出，盯座位区。座位网格始终是一整片暗色矩形；`04-show-start.png`、`07-finale-empty.png`、`10-house-closeup.png` 里我都无法稳定辨认“观众/被照亮的人”，只有 1–2px 级亮斑，无法确认是观众、灯具还是噪点。代码侧印证：观众是 `0.09×0.07` 世界单位的手机灯平面（`src/three/instancing.ts:112`），被照亮后亮度只在 `0.5–1.1` 倍间变化（同文件 183-194）；768 座里几十人时，投影到 1280×720 基本是亚像素。
- 期望：**把“被照亮的人”做成一眼可见的强反馈**——被光照到的座位/人至少要有：人形站起/荧光棒/色块描边三选二，四区能靠“亮区密度”读出人数差；空场与有人必须一眼可分。否则“你照亮谁，谁就为你唱”的核心承诺只存在于结算页。

### P1 · 点燃的节拍判定没有任何可见反馈；节拍环离视线目标太远
- 复现：按住鼠标在观众席点燃（或看代码 `src/game/store.ts:1116-1129`）。完美/良好/错拍只改变 SFX 音高（84+五度 / 79 / 65+click，`src/audio/sfx.ts:191-211`）与倍率，**没有 PERFECT/GOOD/错拍字样、没有粒子颜色或大小差异、没有光斑脉冲差异**；`src/three/fx.ts:59` 的 `ignite-hit` 是单一预设。节拍环 `.beat-ring` 实测 74×74 CSS px，位于 `(603, 628)`（屏幕底部中央），而瞄准目标在画面上半屏——读拍点必须把视线从观众席挪开。
- 期望：点燃后 0.3s 内给**视觉判定**（文字/环闪/颜色三选一，强弱可分），并让节拍信息靠近准星（光斑呼吸、光标环形拍点），底部环保留作全局参考。否则“按拍点 +1/+2/+3”无法被玩家学习，只能靠耳朵——而设置页明确宣传“关声仍可玩”。

### P1 · 光与和弦的关系完全不可见
- 复现：看 HUD 与四区角标；没有任何“当前和弦”“本区声部（根/三/五/七）”“和弦内/外”提示。代码里 `zoneInChord` 决定 ×1.25 / ×0.75（`src/game/light.ts:355-363`），四区 = 根/三/五/七（`src/data/seats.ts:54-92`），但 UI 只有 `前左/前右/后左/后右` 四个名字。
- 期望：四区角标加声部/当前音级（如“前左·根 A”），当前和弦在节拍环中心或顶栏给一个 1–2 字的显示；和弦外音区给弱提醒（与音频一致）。这是把“12 声部和弦”从背景变成玩法的关键一步。

### P2 · 乐队是静止的低模、无脸、全程背面；唯一的荧光棒钩子与拍点不同步
- 复现：整局盯舞台（`09-band-closeup.png`）。江栖/许燎/闻笙/邵砚没有任何跟拍动作、扫弦、鼓棒起落（`src/three/renderer.ts` 每帧只更新相机/观众/噪音/粒子/FX，成员不更新）；角色按设计“无脸，靠发型与色块认人”（`src/three/models.ts:488`），而相机在舞台后方朝 +z（`src/data/seats.ts:9,33`），**玩家整局看到的是三个背影**。另外开场钩子荧光棒的脉动是 `performance.now()/420`（`src/three/scene.ts:129`），周期约 **2.64s**，与 128 BPM 的拍（0.469s）/小节（1.875s）**不成整数倍**——视觉脉动与音乐节拍不同步。
- 期望：至少给成员**跟拍动作**（点头/扫弦/鼓棒起落，强度随段落），让“乐队在演”成立；钩子荧光棒对齐拍网格（0.469s 或 1.875s），这是最便宜、最提气的改动。背影构图可以保留，但需要“演出感”补偿（汗/呼吸/灯光扫过）。

### P2 · HUD 状态只给图标、账条不可读；升级选择过于前置
- 复现：`贝斯线断了` 在右侧只显示一个 38×38 的插头图标（`src/ui/components/Hud.tsx:261-266`，文字是 `sr-only`），不读代码无法知道要按 E；`账` 条只有一条无刻度的比例条，我在 2:26 读到 `convert 0% / burn 100%`，终局结算却是 `转化/烧死 86%`，过程中无法用 HUD 判断自己在“养人”还是“杀人”。另：第一局第 1–5 次三选一分别出现在约 0:50 / 1:20 / 2:0x / 2:26 / 3:48（`05/06-levelup-card*.png`），前 4 分钟被 5 次弹窗打断，节奏体验碎。
- 期望：图标旁给 3–5 字操作提示（“贝斯线断 · E 插线”）；账条加“转/烧”分色 + 刻度或最近 10 秒趋势；把三选一稍微摊平（或让“核心”之外的首选延后到有第一波转化之后）。

### P3（附带记录）
- 在线版 console 有 1 条错误：`favicon.ico 404`（单文件版没有）；Network 除文档外全是内联 `data:` 资源，符合“零外部素材”。若宣传“console 0 条”，Pages 版需要补 favicon 或忽略该项。
- `Esc 暂停 · Tab 看构筑` 叠在观众席中部、低对比（`04-show-start.png`），而 `Tab` 与 HUD 提示不一致（README 已知限制 10）。
- 歌单页（`02-setlist.png`）只有叙事，没有 128 BPM / 4/4 / 304 小节 / 曲目结构；对音游/乐队粉是浪费一块最好的“曲目介绍”位置。
- 升级弹窗打开时局内时钟冻结，但我实测**音乐调度器仍在建音符**（45s 内 oscillator starts 约 +1100、buffer source 约 +750）。若音频没有同步 duck/暂停，恢复后画面拍点会与听到的音乐错位；请人耳确认这一点（我无法听）。

## 4. 最想优先改的三件事

1. **让观众与光斑可见**（P1 #1）：被光照到的人要站起来/亮荧光棒/被描边，四区靠亮度密度读人数；这是“乐趣从无到有”的开关。
2. **给节拍判定可见反馈 + 把拍点放到视线内**（P1 #2）：PERFECT/GOOD/错拍必须有视觉差异；节拍环不能只在屏幕最底部。
3. **把和弦/声部做成 HUD 可读**（P1 #3）：四区角标显示声部与当前和弦，和弦外音区给提醒；顺手给乐队加跟拍动作（P2），让“少女乐队”在画面上成立。

## 5. 再玩 / 推荐

- **愿意再玩 1–2 局**：为了亲耳验证 6:30 静默段、12 声部合唱与“少一轨”的痛感，以及试一次 `回照/独奏流`；但**不会把它当作音游长期练**——目前没有可学的判定反馈，也没有可读的谱面/拍点信息。
- 推荐对象：喜欢氛围、概念、Livehouse 叙事与“注意力即资源”的玩家；**不建议**以“音游/打歌”期待推荐给音游玩家，除非先修 #1–#3。

## 8. 如果只能改一行

把 `beat-ring` 从屏幕底部搬到准星附近，并让完美点燃的环闪出**可见的**“PERFECT”。——这是我从“看不懂”到“想练”的最短路径。
