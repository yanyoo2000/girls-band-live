## 1. 计票方法

1. **独立性**：7 位打分员各自独立完成打分表，均声明未阅读其他打分员文件；本文件只做汇总，不做任何调分、取舍或「去掉最高最低分」。
2. **维度中位数**：对每个方案、每个维度，取 7 个分数的**中位数**（7 个值排序后的第 4 个）。
3. **加权**：总分＝Σ（维度中位数 × 新权重），保留 1 位小数，**四舍五入（.x5 进位）**。
4. **否决**：新规取消可行性否决；仅保留硬约束（离线、桌面、原创、单文件、零外部素材）作为底线。三案均未违反。
5. **乐趣底线**：冠军 Fun 中位数须 ≥ 7；否则最高分夺冠但须在 GDD 前提交「乐趣抢救补丁」。
6. **平局**：Fun → Originality → Theme 的中位数依次比较。
7. **数据完整性**：7 份打分表均含 7 个维度的完整整数行；21 个加权总分已逐项复算，与各表自报值全部一致（见 §3 与 §9）。

> 为什么中位数：7 位打分员的视角差异很大（速通给 B 第一、新手给 B 最后），中位数能吸收两端异常值，比平均数更适合「独立打分 + 不允许互看」的流程。

## 7. 冠军、亚军与选择理由

### 7.1 结果

| 名次 | 方案 | 加权 | 一句话 |
| --- | --- | ---: | --- |
| **冠军** | **Hybrid C《谁在听》** | **7.8** | 一束有代价的光：照向台下，他们为你燃烧，噪音也循光而来；养人—招灾—唱化—放下光。 |
| 亚军 | Hybrid B《松手》 | 7.2 | 舞台是一把走音的六弦巨琴；踩弦—松手把人弹回座位，六音→一音向下成长，敌人无声。 |
| 第三 | Hybrid A《暖场》 | 6.9 | 一首 6:30 的固定歌，一座会越唱越小的台子；按住空格收手，鼓棒到顶砸回去。 |

### 7.2 为什么是 C

1. **新权重下它三项全高。** Fun 30 + Theme 20 + Originality 20 = 70% 的权重；C 的中位数是 **8 / 8 / 8**，B 是 6 / 7 / 9，A 是 7 / 6 / 7。C 是唯一在三个高权重维度上都不低于 8 的方案；B 的原创性优势（9）被 Fun 的 6 和 Theme 的 7 抵消。
2. **它是唯一自带重开驱动的循环。** 「养人 → 更强 → 招来更多噪音 → 更多人」是正反馈；A 是零成长（手法），B 是负成长（失去）。在「一切追求最好的游戏」的标准下，「第二天还想再开一局」比「第一局最稳」更接近「最好」。
3. **共识最强。** 3/3 评审排序 C > B > A；7 位打分员中 6 位把 C 排第一（唯一例外是速通/高难视角，见 §7.4）。这不是制作人偏好，是独立判断的收敛。
4. **它的短板可以靠规则修复，且不需要重做底层。** 假构筑、驻光解、HUD 矛盾、90 秒门、角色工具化——都是 M4 可写进验收矩阵的规则问题；而 B 的前四分钟赤字、负成长与音色命门是结构性的，A 的深度与主题缺口是结构性的。
5. **规则变更没有制造冠军。** 旧权重下 C 仍以 7.70 排第一（§3 对照表）。

### 7.3 为什么不是 B（最强亚军）

- B 的 Originality 中位数 **9**（三案最高，且 7 位打分员一致给 9），Theme 7，机制/主题/镜头同构最强，是「最不可替换」的一案。
- 但它输在：Fun 中位数 **6**（前 4 分钟赤字、观众坐下后不参与输出、10–12 分钟）、Theme 7（「打粉丝」读法风险与孤独基调）、Depth 7 与 Polish 7 并不足以补回 0.60 的差距。
- **B 没有被「难度」扣分**：Feasibility 中位数 8，critic-feasibility 也明确说「不否决」；它输在乐趣与主题，不输在工程量。
- **保留价值**：B 的「松弦回色」（31 人同帧、半空变彩、坐下鼓掌）是全项目最强的单帧。M4 可以把它作为 C 的「转化瞬间」参考（C 的灰→彩 0.8 秒已借用同一语言），但不得把 B 的六弦机制偷渡进 C 的范围。

### 7.4 为什么不是 A

- A 是最稳、最便宜、最不会在 M6 崩的一案；但 Depth 中位数 **5**、Theme **6**，且评委一致指出「四人里三人是炮台+一条规则」——它更像一台优秀的节奏街机，不像「少女乐队」。
- 新规则下 Feasibility + Scope 只剩 10%，A 的 9/9 只能换回 0.90 分；它的 Fun 7、Orig 7 也不足以挑战 C。

### 7.5 反方意见（如实记录，不构成翻案）

- **judge-speedrun**：把 B 排第一（7.9），C 最后（7.3）；理由是 C 的 8 张卡是假构筑、可能推出「驻光不动」的最优解、11 分钟一局还带死尾。**这条直接决定了 C 的 M4 必修项（见 §8）。**
- **judge-newbie**：把 B 排最后（6.6），A 第二（6.7）；理由是 B 前 2:40 无鼓、无第二人、画面像木板。**这与 B 的 Fun 中位数 6 一致。**
- **judge-hardcore**：C 的 7.4 分是「赊账」——在 90 秒切片证伪「只走+看」之前不算成立。**这条进入 M4 验收（§9）。**
- **critic-player**：三案共同的短板是「角色工具化」；C 的队友只是三根线，M4 必须补「角色瞬间」，否则冠军会被读成「乐队主题的幸存者」。
- **critic-fun**：C 的「反被动补丁」可能反向强化驻守；必须用 90 秒切片验证。
- **judge-musicfan**：若光的移动不跟拍或不跟和声，C 会退化成灯光秀；这是 C 的主题生死线。

**结论**：反方意见集中在 C 的三个可修复项，而不是 C 的循环本身；制作人判定它们不构成翻案，但全部转为 M4 硬约束。

## 8. 范围裁剪（冠军 C）

### 8.1 必须保留（身份，砍了就不是 C）

1. **一束有代价的光**：三个去向（观众 / 噪音 / 自己），彼此抢同一束光。
2. **烧 vs 唱化**：快而不可逆 vs 慢而转化成观众；两者必须有真实取舍。
3. **观众三态 + 热度衰减**：灰（未决定）/ 彩（自己人）/ 黑（噪音）；离开光会褪色。
4. **座区声部合唱**：不同区域唱不同音级，光移到哪一区，哪一区的和声就亮。
5. **人浪**：观众阈值触发，把一片噪音唱成人；正反馈的可见形状。
6. **静默段**：Boss 抽走音频总线，只剩视觉节拍；玩家盲奏撑过。
7. **终曲放下光**：唯一按键，镜头翻转；人够＝观众照亮你，不够＝空场。
8. **空场结局**：没有观众也把剩下的段落弹完，不骂玩家。
9. **失败形状**：演出中断（安可消耗人）／空场；没有「你死了」。
10. **结算显示空位与真实数据**，不是击杀数。

## 10. North Star

> **让玩家在 9–10 分钟里学会一件事：你看哪里，决定谁被照亮、谁被吞掉。**
>
> 你养大的一屋子人，既是你唯一的声音，也是你招来的危险；你越亮，越多人来，也越多人想吃掉你。
> 一局结束时，玩家应该能说出：**「是我把这一屋子人养出来的，也是我把噪音招来的。」**
> 然后想再开一局——不是为了更高的分，是为了养得更大，或者救得更少。

## 11. 给 GDD 的硬约束

> **最终内容数量由 M4 的 GDD 锁定；本文件不预设 3 / 6 / 8 等任何数量。** `hybrid-c.md` 里的「4 角色 / 1008 座 / 8 卡 / 4 噪音 / 3 阶段 / 9–12 分钟」是**提案估计**，不是承诺；GDD 可以改数量，但必须满足以下体验与规则。

1. **单局完整弧**：序曲（学会走与看）→ 人浪（第一次「我养出来的」）→ 静默（系统夺走声音）→ 终曲（放下光，可失败）→ 结算（空位与真实数据）。一局至少两个可被复述的时刻。
2. **光必须有代价**：三个去向互相排斥；照观众→招噪音；照噪音→观众冷却；照自己→人气流失。不得出现「无代价的看」。
3. **观众只有一个主定义 + 一个副定义**：主定义是「弹药与血条」，副定义是「记忆」。不得同时当乐器、存档、道德对象；这决定 M4 的实例结构、音频总线与结算。
4. **失败不是死**：演出中断（安可消耗人）与空场（一个人弹完）两种；没有死亡画面；失败归因 3 秒内可读。
5. **音乐因果可听**：光的有效性必须跟拍或跟和声；否则 C 退化为灯光秀，GDD 不予通过。
6. **可读性预算**：全场三色（灰/彩/黑）；一拍只允许一个可读事件；关掉声音也能玩；光锥不得遮挡敌人轮廓。
7. **角色是人，不是线**：每名成员一句话可辨（她是谁 / 她怎么打 / 她怕什么），每名成员至少一个不靠立绘与配音的角色瞬间（成员数由 GDD 定）；队友的三条线必须有主语。
8. **技术硬约束**：桌面键鼠；离线单文件；零外部素材；1280×720/60fps；无每帧 `setState`；真 SpotLight ≤2；后处理不进 MVP；无低画质档不得过 M5。
9. **音频前置**：60 秒垂直切片（五轨可增减、少一轨疼、隔天能哼、静音可玩）在 M4 门禁前通过；C 的合唱用固定声部池（数量由技术方案定，优先 8–12），失败降空间混响，不降概念。
10. **时长**：目标 9–10 分钟，下限 8:30；保留 2:00 人浪、6:30 静默、终曲。GDD 若改时长，必须保留完整弧。
11. **原创与合规**：标题/乐队名/角色名/曲名原创；不影射现实乐队、歌曲、艺人、动漫角色、商标；人群表现不做受伤/窒息/踩踏（`lineage.md` §4 红线）。
12. **不预设数量**：角色、座区/声部、噪音种类、Boss 阶段、卡数、道具、曲目数——全部由 GDD 按「能否服务 §10 的 North Star」决定；本文件只锁规则与体验。
