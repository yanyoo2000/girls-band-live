## 0. 结论

**技术上前置条件全部满足；「能听」有强证据；「想跟着抖腿」没有被证明，而且我知道它最可能死在哪。**

- 60.000 秒整循环（512 步 × 117.1875 ms，零取整误差），实时播放实测跨过 2 圈（`loopCount: 2`）。
- 峰值 **−2.07 dBFS**，RMS **−15.74 dBFS**，**削波样本 0**；软削波 + 压缩器把动态压住但没有压死（段落弧线 6.6 dB）。
- 节拍可测：16 分网格上正拍比反拍高 **10.0 dB**；拍/小节自相关 **0.57 / 0.78**；最佳周期 0.94 s（两拍）。
- 静音是**真正的数字零**：静音、按住抽走两种路径下，输出 RMS 均为 **0（−180 dBFS）**，不是「变小」。
- 五层都能独立测到信号：副歌 8 小节独奏 RMS 为鼓 −18.27、贝斯 −18.31、和弦 −19.80、主旋律 −20.27、琶音 −29.96 dBFS；能量占比 29.5 / 29.2 / 20.7 / 18.6 / **2.0** %。
- **最有效的一层是鼓**（它几乎单独撑起了节拍自相关与正/反拍对比）；**最糟的一层是琶音**（混音里 2.0%，很可能听不见），其次是偏「垫」的和弦层。
- 页面无未处理错误：控制台 0 条消息，页面内错误框为空，运行日志 `kind === 'err'` 计数 0。

**一句话给评审**：这版切片可以拿去做 10 人盲听，但它现在更像「一版结构正确、混音偏暗、鼓点完全量化的 demo」，而不是「一听就想抖腿的歌」。是否够格，请用人耳判，不要用这份报告里的数字判。

## 2. 如何复现（给人耳验收用）

1. 双击 `prototypes/audio-slice.html`，Chrome/Edge 打开（`file://` 即可，无网络请求）。
2. 点「点击开始 · 60 秒」。浏览器要求用户手势，`AudioContext` 在此创建并 `resume()`；实测状态为 `running @ 44100 Hz`。
3. 听三件事：
   - 第 1 遍：0–7.5 s 只有鼓+贝斯；7.5 s 进和弦；15 s 进主旋律；22.5 s 进副歌（加琶音）；37.5 s 两小节「断奏」（鼓/贝斯抽走，只剩和声与长音）；41.25 s 终段；56.25 s 尾奏。
   - 点层开关，听「少一轨」是否明显（尤其主旋律与琶音）。
   - 按住空格 2 秒再松手，听抽走与砸回是否同帧、是否有爆音。
4. 点「离线渲染 60 秒并测量」，在控制台执行 `window.__audioReport` 读取全部指标；页面底部也会显示耗时。
5. 点「渲染并下载 60 秒 WAV」得到 10.09 MiB 的 16-bit PCM 文件，用于盲听（**WAV 只是人耳验收的临时产物，不是游戏交付物**；成品仍必须零外部音频）。
6. **保持标签页可见**：后台标签页会暂停 `requestAnimationFrame`、拖慢离线渲染（见 §5.6）。

## 3. 音乐规格（全部写死）

| 项 | 值 | 为什么 |
| --- | --- | --- |
| BPM | 128 | 与《暖场》一致；16 分音符 = 0.1171875 s，32 小节 = **恰好 60.000 s** |
| 调式 | A 小调（自然小调 + 和声小调属和弦 E） | 少女乐队流行摇滚的常用调；五声旋律不易撞错 |
| 拍号 | 4/4，32 小节 | 512 步，循环无取整误差 |
| 和弦进行 | `Am F C G` ×3，`Am F C G Am F Dm E`（副歌 8 小节），`F G`（断奏 2 小节），`Am F C G Am F G Am`（终段 8 小节），`F G`（尾奏 2 小节） | i–VI–III–VII 的流行摇滚骨架；Dm–E 提供副歌后半的张力；F–G 回 Am 做循环 |
| 曲式 | 前奏 4 / 主歌 4 / 预副歌 4 / 副歌 8 / 断奏 2 / 终段 8 / 尾奏 2 | 60 秒内能听到「加层 → 满 → 抽走 → 回来」 |
| 主旋律 | 8 小节 hook：A4-C5-E5-D5-C5（第 1 小节），重复 + 尾句改写；终段换 G/Am 收束 | 可哼、可背板；不依赖随机 |
| 自动编曲 | 每段写死启用哪些层；手动层开关叠加（手动关 = 不调度） | 「层次增减」既自动可听，也可手动 A/B |

**层次增减是写死的，不是随机的**：段与段之间只改「哪些层被调度」，不改音量自动化。这样同一份数据既喂音频、也喂网格，符合 A 案「16 步单一数据源」的验收要求。

## 4. 五层实现（纯 WebAudio，零素材）

| 层 | 合成方式 | 关键参数 | 频段分工 |
| --- | --- | --- | --- |
| 鼓组 | 正弦下扫 kick（158→44 Hz，0.42 s 衰减）+ 噪声 click；军鼓 = 带通噪声（1.9 kHz）+ 186 Hz 三角；踩镲 = 8.2 kHz 高通噪声（闭 35 ms / 开 220 ms）；吊镲 = 4.8 kHz 高通 1.3 s | kick 峰值 0.58–0.68；snare 0.28–0.34；hat 0.07–0.1；每小节 0/6/8/14 底鼓、4/12 军鼓；副歌 16 分踩镲 | 40–200 Hz + 7 kHz 以上 |
| 贝斯 | 锯齿 + 同频正弦（0.7 / 0.55），低通 560→270 Hz（Q 3.2），5 ms attack | 峰值 0.25，sustain 0.18；8 分根音，6/14 加八度，副歌插 3/11/15 的 ghost 与五度经过 | 80–300 Hz |
| 和弦 | 3 音 saw、±7 cents detune、低通 1.5 kHz、慢起 160 ms 的 pad；另加 2.7 kHz 低通的 saw stab（step 6/11/14） | pad 0.28、stab 0.115；断奏段整体 ×0.6 | 300–2 kHz |
| 主旋律 | 双 saw（detune 7 cents）+ 5.2 kHz→1.9 kHz 低通 + 5.2 Hz 轻颤音；附点 16 分延迟（0.3516 s，反馈 0.24） | 峰值 0.19；8 小节 hook | 600–4 kHz |
| 琶音 | 三角波 + 5.2 kHz 低通 + 短包络 140 ms；左右 pan ±0.35；延迟发送 | 峰值 0.17；8 分音符，和弦音循环 +12 | 1.2–6 kHz |
| 总线 | 5 条层总线 → 压缩器（−18 dB / 3.5:1 / 4 ms / 220 ms）→ 6 kHz 高架 +2.5 dB → 总音量 → tanh 软削波 → 抽走 → 静音 → Analyser → destination | 侧链：每次 kick 把贝斯总线下压到 0.52（14 ms 起、100 ms 回） | — |
| 空间 | 程序化 2.4 s 混响 IR（20 ms 预延迟 + 指数衰减噪声 + 两次早期反射），和弦/主旋律/琶音/军鼓各有发送 | 混响返回 0.55 | — |

**「抽走」的链路位置**：`comp → air → master → softclip → hold → mute → analyser`。`hold` 与 `mute` 在压缩器**之后**，所以抽走/静音会把混响与延迟的尾巴一起切掉——这是《静场》《杂音》要的「不是变小，是抽走」。实测两种路径的输出 RMS 都是 0。

**调度**：`setInterval(25ms)` + 150 ms lookahead，所有音符用 `AudioContext.currentTime` 的绝对时间排程，不用 `rAF` 计时（rAF 只做视觉）。若发现调度落后（后台标签页把 timer 节流到 ≥1 s），丢弃已过去的网格并对齐到当前时间，**宁可留一个洞，也不让一堆音符同时补响**；`lateTicks` 计数可查。

## 6. 听感判断（诚实分层）

### 6.1 「是否达到能听」——是，技术证据较强

我能证明的「能听」是：有清楚的拍点、有低频厚度、有和声、有可哼的旋律、无削波、无爆音、静音干净、循环无缝。这些是「可听」的必要条件，不是「好听」的充分条件。

### 6.2 「是否想跟着抖腿」——未证实，我不能签字

「想抖腿」至少需要三件事同时成立：脉冲清楚、音色有吸引力、编曲有呼吸。本切片只对第一件给了数据（正拍 10 dB 对比、自相关 0.57/0.78），第二、三件只能由人耳判断。

我给三个**可证伪**的预测，供 10 人盲听直接打脸：

1. 多数人能跟着 128 BPM 拍手（正拍/反拍差 10 dB，kick 在 0/6/8/14）。
2. 多数人听完 2 遍能哼出 hook 的前 5 个音（A4-C5-E5-D5-C5），因为它出现 2 次、每次 8 小节。
3. **「想抖腿」最可能死在「鼓点 100% 量化、没有 swing、没有力度变化」**——现在每个 kick 的力度、每个 hat 的时值都一模一样，像鼓机而不是鼓手。这是我认为最可能的失败点，也是最小补救的第一条（见 §8）。

### 6.3 哪一层最有效 / 最糟

| 判断 | 层 | 依据 |
| --- | --- | --- |
| **最有效** | **鼓组** | 独奏 RMS 最响（−18.27）、峰值最高（−1.78）、能量占比 29.5%、正/反拍对比的主要来源、自相关主要由它撑起。没有它，整首立刻塌成「pad 垫乐」 |
| 次有效 | 贝斯 | 29.2%，低频厚度的来源；但也是「闷」的主因（全曲 57.9% 能量在 200 Hz 以下） |
| 中游 | 和弦 | 20.7%，能听出和声，但 350–600 Hz 与贝斯/鼓重叠，容易被掩蔽；听起来更像「垫」而不是「节奏」 |
| 偏弱 | 主旋律 | 18.6%，独奏 −20.27 dB，峰值 −6.88；能辨，但不够「领奏」，在副歌里被鼓/贝斯压住 |
| **最糟** | **琶音** | 2.0%，独奏 −29.96 dB；在混音里很可能**根本听不见**，更谈不上「能听出少一轨」 |

**另一个明确问题**：高频只占 4.7%，整体偏暗。踩镲与琶音都太轻，导致「空气感」不足；这会让切片听起来「闷」「像 demo」，而不是「亮的现场」。

## 7. 提案能力验证矩阵

## 9. 若达不到「想抖腿」，最小补救（按性价比排序）

1. **给鼓加人味（最便宜、最可能有效）**：在 16 分网格上给 kick/snare/hat 加 ±3–8 ms 的固定偏移表 + 每拍 ±2 dB 的固定力度表（写在数据里，不用随机，保持可背板）。现在的问题是「像鼓机」。
2. **低频让位**：kick 与贝斯抢同一频段。把 sidechain 从 0.52 再压到 0.35，释放从 100 ms 缩到 60 ms；或给 kick 加 60–80 Hz 的 shelf +2 dB，让「胸口」更清楚。
3. **补高频**：踩镲 0.07 → 0.1、琶音再 +3 dB、加一层 8 分 shaker（噪声 12 ms），把 4.7% 的高频拉到 8–10%。
4. **和弦给节奏**：pad 目前一小节一换，缺推动。在 step 3 / 11 加 off-beat stab（已有 6/14），或把 pad 的低通做每小节一次的开合。
5. **主旋律抬 2–3 dB**：现在 −20.27 dB，被鼓/贝斯压住；副歌可以让它和 lead 的延迟一起抬。
6. **B 案专用**：如果 M3 选《松手》，下一个切片必须做「六弦 + 断弦 + 调弦」的 A/B，KS 单弦听起来像不像吉他要人耳定；若像玩具，按方案降级到 2-op FM + 琴体 EQ。
7. **C 案专用**：8 声部池「变厚」必须用「声部数 × 每声部 −3 dB」的增益补偿，否则只是变响；这需要单独的人耳 A/B。

## 10. 最大风险与下一步

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| **技术通过 ≠ 好听** | 本切片证明了「能出声、能循环、能静音、能分轨」，没有证明「想抖腿」；这两件事之间隔着编曲与混音 | 立刻做 10 人盲听；不要用本报告的数字替代 |
| **鼓点完全量化** | 最可能的「不像乐队」来源；现在 100% 在网格上、力度恒定 | 补救 1（固定偏移/力度表），不引入随机 |
| **混音偏暗** | 高频 4.7%、低频 57.9%；「闷」是第二个失败点 | 补救 2 + 3 |
| **后台标签页不可靠** | 后台 rAF 暂停、离线渲染 1× 实时；实时调度需要落后保护 | 已验证保护逻辑；M5 建议用 Worker/AudioWorklet 调度，或至少 250 ms lookahead |
| **单文件体积** | 10.09 MiB 的 WAV 只用于试听，**不能进游戏**；游戏仍必须零音频文件、纯合成 | 报告与页面都写死这一点，避免被误当交付物 |
| **B 案音色是主题级风险** | KS 是否「像吉他」没验证；方案自己写了「像玩具就出局」 | 下一个切片优先做六弦 A/B |

**下一步（如果评审要我做）**：
1. 按 §9 的 1–5 做一版「人味 + 高频 + 低频让位」的 v2，再测同一套指标；
2. 做 10 人盲听的记录表（谁、听几遍、能否拍手、能否指出少一轨、隔天能否哼）；
3. 若 M3 选 B/C，各做一个 30 秒的专项切片（六弦 / 声部池）。
