## 1. 结论（给制作人）

**能玩、能跑完 9:30、能结算、能重开，无白屏/崩溃/控制台报错（新页面加载 6 秒内 0 条 console/异常）。但作为首发体验，M6 版本“不好玩”。**

一句话：**这是一个“唯一武器是光、却看不见光、也看不见你在照谁”的版本；而且不操作 55 秒就空场——序曲（GDD 设计为温柔开局）是全场失血最快的一段。**

三条证据（下面都有复现与截图）：

1. **不操作 = 55 秒空场**（局 D2：光放在台上，85 秒采样，t=55 白光已到上限 0.85）；
   **开局 4 秒就被返听锁定**、**8 秒过热**（局 C，日志 t=4/t=8）。
2. **GDD §14 的 1:12「最后一排最右一根荧光棒」这个 90 秒门钩子在实机里不存在**：`src/data/segments.ts:284` 有数据，但 `src/game/`、`src/three/`、`src/audio/` 无任何引用。
3. **走到舞台后侧（按 W 约 2 秒）后画面被相机钻进鼓台 + 白光洗白，整屏空白**（`camera-back-of-stage.png`）；而**按 S 走到台前，观众席才进入画面中部**（`camera-front-of-stage.png`）——纵向轴与画面直觉相反，新玩家第一个动作大概率是 W。

**结论：AC-13 / AC-H01（10 名新玩家 90 秒门 ≥7/10）现在不具备开测条件**，应先修 §7 的 H1–H4，再由真人做门禁。

## 3. 90 秒门行为（本次最重要的一节）

### 3.1 实测

| 行为 | 结果 |
| --- | --- |
| 开局光位 | **由“开始演出”按钮的鼠标位置决定**（`src/game/light.ts:195` 每 tick 用 `input.pointerWorld` 覆盖目标），data 的 `initialLightPosition`（前排正中）被瞬间覆盖。局 A/C 登录时都落在**前左区**（按钮在屏幕左侧）。 |
| 返听锁定 | **t=4s**（局 C 日志，`statuses: ["返听锁定"]`，toast「返听锁定了你的光」） |
| 过热点 | **t=8s**（局 C，`前左区，热度抬头，过热点`） |
| 不操作的损失速度 | 局 D2：**t=55 白光 0.85 = 30 人全部离场**（`log-runD2` 采样：7s/0.057、19s/0.255、30s/0.425、43s/0.595、55s/0.85） |
| 20 秒不动再开始玩 | 局 C：t=20 时白光已 **0.425**（约掉一半），此后扫场只能“止血”，回不到峰值 |
| 1:12 的“唯一荧光棒”钩子 | **不存在**（数据有、代码无引用） |

### 3.2 判断

GDD §14 写的开场是：序曲无噪音 → 1:12 最后一排最右一根荧光棒亮起 → 玩家自己把光移过去。**实现里反过来了**：

- 序曲没有噪音，所以“威胁”全部来自**返听锁定（4s）+ 过热（8s）+ 未照亮座位冷却离场**；
- 开局光位跟着鼠标落在某个区，玩家不动就立刻进入压力状态；
- 于是“最该安全的第一分钟”变成“掉人最快的的一分钟”，而 GDD 用来钓住玩家的 1:12 邀请没有实现。

结论：**90 秒门当前不是“玩家会不会主动移光”，而是“玩家能不能在看懂之前别把场子输光”。** 这不是数值微调能解决的，属于 H1/H2 两条必修。

**驻守确实被惩罚**（F3 数值方向正确），但**惩罚过重且对“什么都不做”也生效**：光不在座位上时**座位冷却离场**同样清场，玩家没有任何“先看一会儿”的容错。建议接受 `dwellRewardRatio < 0.75` 的设计，但把“冷座位离场”与“驻守惩罚”分级：序曲不因冷却掉人。

## 6. 可读性与手感

**画面**
- **光在哪：看不见。** 1280×720 下我没有找到可辨认的光斑/光锥，只能靠「四角热度点 + 座位颜色」反推；而四角区点本身位置是错的（M1）。
- **观众席怎么看：弱。** 默认站位观众席只占画面上部一条暗带（`runC-11-first-light-move.png`）；按 **S** 走到台前才是可用视角（`camera-front-of-stage.png`，观众席占画面中部）。座位本身就是大块浅灰几何，人的状态（灰/彩/黑）表现为座位变色，30 人时只看到 2 个粉色座位。
- **白光**：到 0.42 就把整屏洗成灰白（`runC-18-pause.png` 背景）；与“相机钻进鼓台”叠加时画面完全空白（`camera-back-of-stage.png`）。
- **节拍环**：74×74 区域在最底部、与主唱麦克风高光重叠，截图里只有 1 个点可见（`evidence-beatring-crop.png`）；“落在拍点上伤害更高”几乎无从判断。

**手感**
- 键鼠可用，点击/按住左键（束光）触发正常；鼠标移动→光有惯性（`approach`），但因为没有光斑，判断不了延迟。
- **WASD 纵向轴与画面直觉相反**：W（上）把主唱往鼓台方向走，画面立刻钻进鼓组；S 才是朝观众席走。系统提示只写「WASD 移动主唱」，没有“往台下走”的引导。
- 三线断裂只有一次性 toast「靠近队友，按 E 插线」+ 右侧三个橙色插头图标，**没有方位指示**；我 3 次试玩都没成功插上线（队友在身后两侧，需要先走向舞台后侧，而那里相机已经不可用）。
- 帧率：1280×720 视口下 4 秒采样 **平均 50.5 fps、p95 帧间隔 17ms**（背景标签页 + focus emulation；非正式性能验收，仅作“没卡死”的证据）。

## 7. 缺陷清单（复现 → 期望）

### blocker
无。四次会话全部能启动、能进入演出、能结算、能重开；无白屏、无异常。

### high

**H1 开局 4 秒返听锁定 / 8 秒过热，序曲成为全场最难的一段**
- 复现：`file://` 打开 → 进入后台 → 开始演出（鼠标停在按钮上）→ 双手离开键鼠 60 秒。观察：t=4 出现「返听锁定了你的光」，t=8 前左区过热，白光在 55 秒内吃满，人气归零。
- 原因：光位每 tick 跟随指针（`src/game/light.ts:195`），开局指针停在“开始演出”按钮 → 光直接落在一个区内；锁阈值 4s（`balance.heat` 相关常量 / `enemies.updateReturnListener`）、过热 8s（`balance.heat.overheatSeconds`）。
- 期望：序曲（0:00–1:30）不进入返听/过热压力；或开局光位固定在舞台（非座位区），并给 ≥30 秒无惩罚观察期。

**H2 GDD §14 的 1:12「唯一荧光棒」钩子未实现**
- 复现：跑任意一局到 1:12，最后排右端没有任何单点高亮；`grep -rn "OPENING_HOOKS\|last-row-invite" src/game src/three src/audio` 无命中。
- 期望：实现该座位 `phone=1` + 唯一高亮与音效（这是 AC-13/AC-F04 的钩子），或从 GDD 删掉并重设钩子。

**H3 走到舞台后侧后相机钻进鼓台，画面不可用**
- 复现：开始演出后按住 `W` 约 2 秒（`camera-back-of-stage.png`、`runC-13-after-W.png`）。观察：整屏被灰色几何/白光吞掉，看不到台面、成员、观众席。
- 原因：`src/three/camera.ts` 在目标 z 变小时水平距离被压到 `CAMERA_LIMITS.minHorizontal=6`，俯角变陡贴到鼓台（源码注释已承认是“可接受取舍”）。
- 期望：对鼓台/后墙做遮挡回避（抬高机位或拉近距离），保证任何站位都能看见台面 + 至少一角观众席。

**H4 白光在 0.42 就把画面洗白，和 H3 叠加后完全不可读**
- 复现：任何掉一半人的局面（局 C t=120 起白光 0.453，`runC-19-chorus-220.png` / `runC-18-pause.png` 背景）。
- 期望：白光上限降到 ≤0.35 或改为边缘渐晕；“能看见观众席”优先级高于“洗白表现”。

### medium

**M1 HUD 四角区点与座位在屏幕上的实际位置上下颠倒**
- 现状（已核）：`src/styles/ui.css` 把 `front-left` 放 `top:42px`、`back-left` 放 `bottom:0`；截图里左上角确实是圆形点+「前左」（`evidence-zonecorner-crop.png`）。
- 矛盾（已核）：`src/data/seats.ts` 的 `corner` 字段写 `front-left='bottom-left'`、`back-left='top-left'`；而相机在舞台后方朝 +z 看，前排（z 小）在画面下方——`camera-front-of-stage.png` 里座位块由近（下方 y≈380）向远（上方 y≈150）抬升，前排在下方。
- **实机热度复现未完成**（本轮最后几次尝试都在空场局，读不出区热度）：建议 t116 用一局有人气的存档，把光指向画面**上部偏左**，看亮的是左上（前左，则 CSS 正确、data 的 corner 写错）还是左下（后左，则 CSS 错）。
- 期望：四角点方位与 `data/seats.ts` 的 `corner`、与画面几何三者一致。

**M2 结算“断线次数”恒为 0**
- 复现：局 A/C 中 HUD 显示「吉他线断了 / 贝斯线断了 / 鼓线断了」，结算后台文案仍是「吉他断了 0 次。她一句都没漏。」（`runA-emptyhouse-results.png`、`runC-99-results.png`）。

- 见 §6 与 `evidence-beatring-crop.png`。期望：放大/提亮/换位（避开麦克风高光），strong/weak 有明确差异。

**M8 断线后无方位指引**
- 复现：三线全断时只有 toast + 右侧插头图标，玩家不知道队友在左后/右后/正后。期望：HUD 给方位箭头或成员小地图；或断线时镜头/描边指向队友。

### low

- **L1** 「空场。只剩你还在弹。跳过剩余演奏」toast 会自动消失，且允许继续弹 6 分钟（局 A）；与“只剩你”的叙事不一致。
- **L2** 文案「第二排还空着 0 个位置」语感不对（0 个还空着）。
- **L3** 结算里「返听咬了你 1 次」等复述数据看起来对，但和断线 0 次放一起会让人怀疑读数（见 M2）。
- **L4** 首次点击后启动页按钮从「点击开始」变「进入后台」，可接受；但“进入后台”与随后“开始演出”的两段式点击缺少必要性提示。

## 8. 整体“好不好玩”判断

**判断：概念有钩子，当前版本不好玩；但可修。**

理由（按重要性）：

1. **看不到自己唯一的武器。** 光是本作的全部操作，却没有任何可见的光斑/光锥；玩家只能从“座位颜色 + 四角小点”间接推断，而四角小点方位是错的。
2. **第一分钟是惩罚，不是邀请。** 4 秒锁定、8 秒过热、55 秒空场；GDD 设计的 1:12 一根荧光棒没有实现。新玩家最可能的结局是“还没看懂就输了”。
3. **节奏断档。** 5 分钟没有一次升级；构筑条空着；卡牌（也就是构筑差异，本作最大的 Roguelike 卖点）在前半场几乎不出现。
4. **工作量大但不可见。** 音频、合唱层、Boss、三线、人浪都在跑，但镜头一旦走到舞台后侧就全屏空白，玩家根本看不到这些内容。
5. **好的部分确实好。** 停手 → 掉人 → 白光涌上来这套“人气＝血条、白光＝被听见的幻觉”的表达到位；Boss 段补人、终曲长按放光的仪式感成立；结算/重开/暂停都顺。

**如果只修 2 项**：H1（序曲免惩罚 + 开局光位不落区）与 H3+H4（任何站位都能看见台面，白光不吃掉可读性）。这两项修完，再补 H2 的 1:12 钩子，才有资格做 AC-13 的 10 人门。

## 9. 未覆盖 / 不能由本报告替代的验收（如实）

- **不是人样本**：试玩者是 AI，已知玩法；AC-H01 的 10 名新玩家、`firstActiveLightMoveAt` 中位数、`lightMovesPerMinute`、`igniteOnBeatRate` 等**不能用本报告替代**。本报告只提供“仪器可用性 + 反例”。
- **听不见**：全程无法评估音频（5 层、12 声部、12 SFX、静默段听感、盲听 A/B）。F11/AC-18 仍需人耳。
- **没测性能验收**：只有一次 4 秒 rAF 采样（50.5 fps / p95 17ms），且浏览器里有其它 agent 的页面同时存在；AC-T14–17 的 60fps/draw call/overdraw 仍需独立复测。
- **没做 1920×1080**：本报告全部在 1280×720。
- **局 B 未完成**（我主动终止，方向假设错误）；**没有从 0 完整打到 A/B 评级**（两局都是 C、峰值 90/104）；**没有触发过“中断/安可”失败卡**（两局都是空场或完成，未走到低人气 8 小节 + 安可已用）。
- **控制台**：新页面加载 6 秒内 0 条 console/异常；局内未装持续监听，故“整局 0 报错”不作断言（t108 已验）。
