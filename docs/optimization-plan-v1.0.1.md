- **日期**：2026-10-28（Asia/Shanghai）
- **作者**：制作人

## 2. P0 必改（5 项）

### P0-1 可见性：光 / 观众 / 噪音 / 四区（t142 已实现，待验收 + t143 补 HUD）

- **问题**：核心机制在世界里不可见；束光前后像素差 0.17%；平均亮度 13–19/255。
- **验收线（可测）**：
  1. 1280×720 固定 seed 截图：整帧均值 ≥32、舞台 ≥35、观众席 ≥32（t142 实测 40.83/39.51/50.82）；
  2. 束光 vs 散光同一姿势、同 seed：观众席区域像素差 ≥6/255 或 ≥2%（t142 实测 14.61%）；
  3. 20+ 噪音场：噪音/精英/Boss 在暗场可辨（描边或光环），四区可凭场景分辨；
  4. 白光 0.85 时舞台区亮度不低于常态 −5%，HUD 文字仍可读（t115 对比度不回退）。
- **影响面**：`src/three/**`（已完成）、`src/ui` HUD 区标（t143）。
- **不做**：不整体提亮到"白"、不加后处理/泛光、不改变美术基调。

### P0-2 卡效果接线 + 局内统计回写（t139）

- **问题**：11+ modifier 无消费方（第二排/合唱墙/decay/shield/self/bait/black/第一排/留人）；`run.stats` 只在结算写 → 账条恒 0%/100%。
- **验收线（可测）**：
  1. 每个原无消费方的 key 至少一个消费点 + 一条单测（t139 交付「逐卡接线表」）；
  2. `第二排`：选卡后 60s 人数 ≥ 选卡时 +8（30s +5 的整数倍），且 HUD 峰值随之上涨；
  3. `合唱墙`：四区各 ≥40 时 `choirDamageForZone` ×1.5，未达时仅基础值（单测断言两分支）；
  4. 局内账条 = 结算转化/烧死（同一数据源；bridge 读新字段或 store 回写）；
  5. 完整 9:30 至少一局峰值 >30 且触发至少一次核心/进化。
- **影响面**：`src/game/**`、`src/data/**`、`src/types/**`、tests；合同变更走 tech-spec §17.2。
- **不做**：不改 24 卡数量、不删卡；无法实现的卡改为等价效果并同步 GDD/卡面。

### P0-3 返听锁定可解 + 兜底（t139）

- **问题**：解锁用「到音箱堆距离 >8m」而非「光心位移 >8m」，观众席内移光解不开，且无超时。
- **验收线（可测）**：
  1. 锁定瞬间记 `lockOrigin`，光心累计位移 ≥8m 即解锁（单测：前排左→右移动 10m 解锁）；
  2. `maxLockSeconds` 6–8s 强制解除，解除有 `return-listener` 事件与音频反馈；
  3. 解除后 ≥4s 冷却，同一返听不立即重锁；
  4. `tests/f3-bot.test.ts` 不回退（camp ≤18 / sweep ≥36）。
- **影响面**：`src/game/enemies.ts`、`balance`、`types`（HUD 倒计时字段）。
- **不做**：不取消反驻守、不放宽到"移光即解"（保留代价）。

### P0-4 人气读数 + 空场预警（t139 字段 + t143 UI）

- **问题**：9/10 人不知道自己在输；白光只表达比例、无趋势/绝对量；首帧 0.85 满白。
- **验收线（可测）**：
  1. 局内仍 0 数字，但 HUD 有：四区亮灯比例、10s 趋势（↑/→/↓）、空位剪影/空场前 10s 预警（边缘脉动+心跳）；
  2. 白光与趋势可区分（白光=比例，趋势=方向），开局 whiteout=0、emptyHud 不闪白；
  3. 新玩家（同批试玩口径）90 秒内能说出「我现在是涨还是掉/大概还剩多少人」。
- **影响面**：`HudSnapshot`/`RunUiFlags`（t139）、`src/ui/**`（t143）。
- **不做**：不显示人数/血量数字；不把白光改成血条。

### P0-5 序曲教学 + 光形态 + 操作一致性（t143）

- **问题**：0–90s 零引导、束光误伤无反馈、形态无指示、Tab/空场 Esc/断线提示不一致。
- **验收线（可测）**：
  1. 0–90s 内嵌三步非阻断教学：移动/散光养人 → 按住左键束光烧人 → 点击点燃；首次束光覆盖观众时红色反馈/人群退开；
  2. 散/束/回三格常驻 + 当前高亮；拿到核心给一行操作说明；回照的护盾/冷却可见（依赖 t139 字段）；
  3. Tab 真打开构筑视图；空场时 Esc/暂停可用；HUD 文案与实现一致；断线图标 +「靠近队友按 E」可读；favicon 404 消除；
  4. 新玩家 90 秒内能说出「散光养人/束光烧人/看哪里招灾」（t143 验收原文）。
- **影响面**：`src/ui/**`、`src/App.tsx`、`src/styles/ui.css`、`src/index.html`、`tests/ui-smoke.test.tsx`。
- **不做**：不新增长教程墙、不改玩法规则、不动 game/data/three/audio 逻辑。

## 3. P1 应改（5 项）

### P1-1 升级节奏与卡面密度

- **问题**：10 次三选一集中在 0:19–5:15（多人实测 4:30 内打完），之后 5 分钟无构筑推进；卡面 4 行 + 3 个无标签旋钮。
- **验收线**：第 10 次选择时间 ≥6:00（三局均值）；核心首选取体验后（或首次选择延后至 ≥0:40）；卡文 ≤2 行；删 3 个无标签旋钮。
- **影响面**：`balance`/`progression` XP 曲线、`ui` 卡面。
- **不做**：不改 24 卡/10 选/3 核心规则；不为节奏删卡。

### P1-2 安可窗口（t139-4）

- **问题**：人气直接归零绕过安可；06 只见过一次（缓慢下滑路径）。
- **验收线**：`present` 首次跌破峰值 8% 触发「告急」（预警）；归零帧若未用安可先弹「安可/继续独奏」；安可恢复 `max(开局30, peak×0.4)` 且 ≤peak；空场仍为完成结局。
- **影响面**：`store.ts` 终局流程、`ui` 中断覆盖层。
- **不做**：不改「空场是完成不是失败」语义；不强制弹窗。

### P1-3 音频收尾验收（t140 已完成）

- **验收线**：空场保留 0.22 心跳/独奏（不永久静音）；合唱 4 档增益 −17.7/−14.6/−11.4/−8.4 dBFS、相对 music −11.6/−8.5/−8.3/−8.3 dB；静默小节量化淡出/淡入 + 心跳；升级 duck 不中断。人耳盲听仍 defer（标注）。
- **不做**：不重写音频引擎；不改 5 层结构。

### P1-4 卡面 / 结算 / 暂停同源 + 进化进度（t143-6）

- **验收线**：暂停面板构筑与 HUD 同源（含核心）；局内账条与结算同源；进化进度「还需 N 张支援」；结算保留现有数据与后台文案。
- **不做**：不删结算页任何现有区块。

### P1-5 无障碍兜底

- **验收线**：<1024×640 不再全屏锁死（给说明 + 键盘出口或"仍要继续"）；失焦自动暂停（与 README 一致）；HUD 小字 ≥11px 且对比度 ≥4.5:1；方向键/小键盘移光兜底（不追求完整键鼠等价）。
- **不做**：不做完整键盘等价光（P2 评估）；不做读屏全流程重写。

## 4. P2 可延后

| 项 | 理由 |
| --- | --- |
| 评级可达性（S/A 阈值） | 需三局成长曲线数据与产品决策；先修卡效果与读数，再评估 |

| Boss 静默可学习性（可视化节拍/阶段提示） | 已有音频与 HUD 提示，先看教学后反馈 |
| 荧光棒与 128BPM 同步 | 表现层小项 |
| 乐队跟拍/动画/无脸 | 美术成本高，不阻塞 |
| 失败原因归因强化（结算加"下次试试"） | 低风险，可随 P1-4 顺手做 |
| 90 秒真人门 / 音频盲听 / 集显性能 / Firefox | 人测 defer，不因 v1.0.1 改变口径 |

## 5. v1.0.1 退出标准（DoD）

1. **四命令全绿**：`typecheck 0` / `test` 全过（含修复 `hud.test` emptyHud 断言）/ `build` ×2 同 SHA / `validate 14/14`。
2. **file:// 9:30 ×3 局**：至少 1 局峰值 >30、至少 1 次核心/进化触发、返听可主动解除、安可窗口至少出现 1 次；console 0、Network 仅 1 条文档请求。
3. **可见性 before/after 截图**：亮度、束光像素差、噪音/四区可辨（t142 口径）。
4. **教学验收**：新玩家（同批试玩口径）90 秒内说出「散光养人/束光烧人/看哪里招灾」。
5. **不回退**：`tests/f3-bot.test.ts` camp ≤18 / sweep ≥36；单文件 ≤2MB；无新增依赖/外部素材；锁定数量不变。
6. **文档同步**：GDD/tech-spec/acceptance 与实现一致；README/CHANGELOG 增 v1.0.1 条目；本轮 10 人反馈结论与 defer 项写进 release notes。
