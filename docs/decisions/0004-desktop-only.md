# 决策记录 0004：仅桌面端，不做移动端/触屏

- 日期：2026-10-28
- 状态：已采纳
- 决策人：用户

## 背景

用户明确要求：这款游戏只需要能够在电脑上操作。此前 brief 中保留了移动端触屏与竖屏适配，增加了 UI、QA 与交互成本；在 10 分钟一局、以 Three.js 3D 表现为主的桌面游戏中，触屏不是必要目标。

## 决策

1. **目标平台**：仅桌面浏览器（Chrome/Edge/Firefox 最新两个大版本，WebGL2）；Safari 17+ 桌面版尽力兼容。
2. **操作**：键盘移动（WASD/方向键）+ 鼠标菜单 + Space「Encore」+ Esc/按钮暂停；不做虚拟摇杆、不绑触屏、不做移动端布局。
3. **验收**：桌面 1920×1080 与 1366×768 各完成一次实机试玩；窗口缩放画布等比适配；不做 390×844 移动端验收。
4. **职责收敛**：`planner-newbie` 从“新手友好与移动端”改为“新手友好与桌面可读性”；`dev-ui` 去掉触屏；`qa-compat` 改为桌面兼容性/无障碍/离线。
5. **旧资料**：旧企划与旧模板中的触屏内容仅作历史归档，不进入新版评审与实现。

## 后果

- UI/CSS 只做桌面响应式，少一套触屏交互与移动端性能调优。
- GDD、技术方案、验收矩阵与 QA 报告必须显式写明“仅桌面”，避免实现阶段又引入触屏需求。
- 若未来要做移动端，需新增决策并重新评估 Three.js 性能、虚拟摇杆与包体。
