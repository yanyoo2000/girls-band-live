# 决策记录 0003：依赖政策放宽为“按需引入、评估记录”

- 日期：2026-10-28
- 状态：已采纳
- 决策人：用户 + 制作人（captain）

## 背景

用户明确要求：不要预设“只能使用 React/Three.js/Vite/TypeScript/Vitest”的死名单，可以根据项目需要动态引入外部框架、库等。项目仍要求离线单文件、原创素材、可维护与可发布。

## 决策

1. **核心栈不变**：React 19 + TypeScript 5.9 + Three.js 0.186 + Vite 8 + Vitest 5 仍是基础。
2. **允许按需引入**：为解决具体问题可以引入其他库/框架（例如单文件构建插件、音频封装、动画、状态管理、测试工具等）。
3. **准入流程**：
   - 由需求方（通常是技术总监或模块负责人）在任务报告/技术方案中提出：解决什么问题、为什么现有栈不够、候选库、包体、许可证、维护状态、离线可用性、供应链风险。
   - 技术总监批准后，记录在 `docs/tech-spec.md` 的「依赖清单」表中，并视情况新增 `docs/decisions/` 记录。
   - 由制作人统一执行 `npm install`，提交 `package.json` 与 `package-lock.json`；成员不得擅自安装。
4. **硬性红线**：
   - 不得引入需要联网运行时、远程 API、CDN 资源的库。
   - 不得引入包含版权素材、字体、音乐、模型、贴图的包。
   - 不得引入无法锁定版本或来源不可信的包。
   - 单文件成品仍须 ≤ 4MB；新增依赖计入包体预算。
5. **复核**：代码审查检查依赖是否登记、许可证是否兼容、包体是否超预算、是否可用标准 API 替代。

## 后果

- 团队可以根据 3D、音频、UI、构建的实际需要选型，不再被死名单束缚。
- 代价是依赖治理成本上升：技术方案必须维护依赖清单，review 必须检查，单文件包体必须持续测量。
- 若最终包体超过 4MB，优先裁剪非必要依赖，而不是放弃单文件交付；确需放宽预算时由制作人提交用户确认。
